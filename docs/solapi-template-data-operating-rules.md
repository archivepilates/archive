# SOLAPI 템플릿 데이터 연결 운영 규칙

이 문서는 ArchiveIN에서 StudioMate/Firebase 데이터를 SOLAPI 카카오 알림톡 템플릿에 연결할 때의 운영 기준이다. 목적은 템플릿별 대상자 선정, 변수 매핑, 제외 조건, 중복 발송 방지를 한 기준으로 맞추는 것이다.

## 기본 원칙

- 알림톡 발송 기준 데이터는 `memberProfiles/{memberId}`를 중심으로 한다.
- 회원 식별은 이름이 아니라 `memberId` 우선, 보조로 `memberPhone`을 사용한다.
- Google 주소록은 보조 저장소이며 알림톡 대상자 원천으로 쓰지 않는다.
- 정산/매출/월간 분석용 엑셀 데이터는 알림톡 대상자 산정에 직접 쓰지 않는다.
- 템플릿 상태가 `APPROVED`가 아니면 실제 발송하지 않고 후보만 생성한다.
- 한 회원에게 같은 날 여러 후보가 생기면 신규회원, 프라이빗 사전설문, 잔여횟수, 잔여기간, 예약안내 순으로 우선순위를 둔다.
- 회원 연락처가 없거나 휴대폰 형식이 아니면 후보는 `skipped`로 기록하고 발송하지 않는다.
- 같은 회원에게 같은 사유의 알림을 반복 발송하지 않는다.

## 공통 데이터 매핑

| 템플릿 변수 | 원천 필드 | 변환 규칙 |
| --- | --- | --- |
| `#{이름}` | `memberProfiles.name` | 회원명 그대로 사용하되 공백을 정리한다. |
| `#{수강권명}` | `memberProfiles.activeTickets[].name` | 대상 수강권 1개만 선택한다. 여러 장이면 가장 먼저 만료/소진되는 수강권을 고른다. |
| `#{남은일수}` | `activeTickets[].expiresAt` | 한국시간 오늘 기준 잔여 일수. 오늘 만료는 `0`, 이미 만료는 발송 대상 제외. |
| `#{잔여횟수}` | `activeTickets[].remainingCount` | 숫자만 전달한다. `null` 또는 기간권이면 횟수권 템플릿에서 제외한다. |
| `#{만료일}` | `activeTickets[].expiresAt` | `YYYY. M. D.` 형식으로 표기한다. |
| `#{예약주차}` | 예약 오픈 기준 주차 | 예: `5/18~5/24` 또는 운영자가 확정한 주차 문구. |

### 1. 신규회원 웰컴 안내

대상:

- StudioMate 회원 등록일이 확인된 신규회원.
- 기존 `memberProfiles`에 동일 `memberId` 기록이 없던 회원.
- 등록일 기준 30일 이내.
- 연락처가 정상 저장된 회원.

발송 시점:

- StudioMate 등록 감지 후 10분 이내 후보 생성.
- 초기 운영 단계에서는 운영자 확인 후 발송한다.

제외:

- 전화번호 없음.
- 기존 회원으로 확인됨.
- 이미 신규회원 웰컴 알림톡 발송 이력이 있음.
- 테스트/직원/미수금 등 운영 제외 태그가 있는 회원.

중복키:

- `new_member:{memberId}`

### 2. 그룹 기간권 잔여기간 안내

대상:

- 활성 그룹 기간권을 보유한 회원.
- 만료일까지 14일 이내.
- 이미 만료되지 않은 수강권.
- 같은 용도의 다른 활성 그룹 수강권을 보유하지 않은 회원.

발송 기준:

- `남은일수`가 `14, 7, 3, 1` 중 하나일 때 후보를 만들 수 있다.
- 초기 운영은 `14일 이내 최초 1회`만 발송한다.

제외:

- 다른 활성 그룹 수강권이 이미 있음.
- 수강권이 환불/사용불가/만료 상태.
- 회원이 프라이빗만 이용 중인 경우.
- 최근 7일 내 동일 수강권 만료 안내 발송 이력이 있음.

중복키:

- `group_period_expiring:{memberId}:{ticketId}:{expiresAt}`

### 3. 그룹 횟수권 잔여횟수 안내

대상:

- 활성 그룹 횟수권을 보유한 회원.
- 잔여횟수 5회 미만, 즉 `1~4회`.
- 같은 용도의 다른 활성 그룹 수강권을 보유하지 않은 회원.

발송 기준:

- `잔여횟수`가 `4, 3, 2, 1` 중 하나일 때 후보를 만들 수 있다.
- 초기 운영은 `5회 미만 최초 1회`만 발송한다.

제외:

- 잔여횟수 0회.
- 다른 활성 그룹 수강권이 이미 있음.
- 기간권처럼 잔여횟수가 없는 상품.
- 수강권이 환불/사용불가/만료 상태.

중복키:

- `group_count_low:{memberId}:{ticketId}:{remainingCount}`

### 4. 프라이빗 횟수권 잔여횟수 안내

대상:

- 활성 프라이빗 횟수권을 보유한 회원.
- 잔여횟수 3회 이하, 즉 `1~3회`.
- 프라이빗 수업 이용 이력이 있거나 예약이 있는 회원.

발송 기준:

- `잔여횟수`가 `3, 2, 1` 중 하나일 때 후보를 만들 수 있다.
- 초기 운영은 `3회 이하 최초 1회`만 발송한다.

제외:

- 잔여횟수 0회.
- 다른 활성 프라이빗 수강권이 이미 있음.
- 그룹권만 보유한 회원.
- 수강권이 환불/사용불가/만료 상태.

중복키:

- `private_count_low:{memberId}:{ticketId}:{remainingCount}`

### 5. 프라이빗 사전설문 안내

대상:

- 프라이빗 수강권을 처음 등록한 회원.
- 또는 첫 프라이빗 예약이 생성된 회원.
- 설문 발송 이력이 없는 회원.

발송 시점:

- 프라이빗 수강권 등록 또는 첫 프라이빗 예약 감지 후 후보 생성.
- 첫 프라이빗 수업 시작 전까지 발송하는 것을 원칙으로 한다.

제외:

- 이미 설문 발송 이력 있음.
- 기존 프라이빗 이용 이력이 있음.
- 전화번호 없음.
- 프라이빗 수업이 취소되었고 향후 예약이 없음.

중복키:

- `private_survey:{memberId}`

### 6. 예약 안내

대상:

- 예약 오픈 안내가 필요한 활성 이용회원.
- 예약 가능한 수강권을 보유한 회원.
- 운영자가 지정한 예약 주차에 수업 예약이 필요한 회원.

발송 시점:

- 매주 예약 오픈 직전 또는 운영자가 지정한 시간.
- 예약 오픈 로직은 StudioMate 정책 변경 가능성이 있어 자동화 전 운영자 확인 단계를 둔다.

제외:

- 활성 수강권 없음.
- 휴면/장기 미방문으로 별도 케어가 먼저 필요한 회원.
- 최근 동일 예약주차 안내 발송 이력 있음.

중복키:

- `reservation_open:{memberId}:{reservationWeek}`

## 후보 상태 운영

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| `candidate` | 규칙에 의해 생성된 후보 | 운영자 화면에 표시 |
| `reviewed` | 운영자가 확인했지만 아직 발송 전 | 발송 대기 또는 보류 선택 |
| `queued` | 발송 큐에 들어감 | 재시도/결과 대기 |
| `sent` | SOLAPI 발송 성공 | 회원카드와 ACTIONS에 기록 |
| `skipped` | 제외 처리 | 사유를 기록하고 같은 조건 반복 노출 방지 |
| `failed` | 발송 실패 | 에러와 재시도 가능 여부 기록 |

## 발송 전 체크

자동 또는 버튼 발송 직전 아래 조건을 모두 통과해야 한다.

1. 템플릿 상태가 `APPROVED`이다.
2. 회원 연락처가 있고 휴대폰 번호로 정규화되어 있다.
3. StudioMate 동기화 데이터가 최신이다.
4. 같은 `dedupeKey`로 `sent` 또는 `queued` 이력이 없다.
5. 대상 수강권이 아직 활성 상태다.
6. 다른 활성 수강권 보유로 제외되는 케이스가 아니다.
7. 운영자가 `skipped` 처리한 후보가 아니다.

## 우선순위

같은 회원에게 같은 날 여러 후보가 생성되면 아래 순서로 하나만 기본 추천한다.

1. 신규회원 웰컴
2. 프라이빗 사전설문
3. 프라이빗 잔여횟수
4. 그룹 잔여횟수
5. 그룹 잔여기간
6. 예약 안내

운영자가 직접 선택하면 같은 날 여러 건을 발송할 수 있지만, 기본 자동 추천은 1건으로 제한한다.

## 기록해야 할 데이터

`alimtalkCandidates/{candidateId}`:

- `memberId`, `memberName`, `memberPhone`
- `templateCode`
- `reason`
- `payload`
- `dedupeKey`
- `sourceDataVersion`
- `sourceSyncedAt`
- `status`
- `reviewedByUid`, `reviewedAt`

`alimtalkSends/{sendId}`:

- `candidateId`
- `templateCode`
- `payload`
- `solapiMessageId`
- `status`
- `attempts`
- `lastError`
- `sentAt`

회원카드:

- 최근 발송 템플릿
- 발송일
- 발송 사유
- 실패/제외 사유

## 운영자 화면 표시 기준

운영자 ACTIONS에는 단순히 "자동대상"으로 묶지 않고 아래처럼 사유를 분류해 보여준다.

- 신규회원
- 그룹 기간 임박
- 그룹 횟수 부족
- 프라이빗 횟수 부족
- 프라이빗 설문 필요
- 예약 안내 대상

각 후보 카드에는 `템플릿명`, `선정 이유`, `수강권명`, `남은일수/잔여횟수`, `최근 동기화 시각`, `발송/제외 버튼`을 표시한다.

## 현재 코드와 맞춰야 할 수정 포인트

- `rebuildAlimtalkCandidates.ts`의 템플릿 ID를 최신 승인 템플릿 기준으로 분기해야 한다.
- 그룹/프라이빗 수강권을 구분해 기간권과 횟수권 규칙을 따로 적용해야 한다.
- `ticket_expiring` 하나로 뭉친 후보를 `group_period_expiring`, `group_count_low`, `private_count_low`처럼 사유별로 분리해야 한다.
- 신규회원 웰컴 v3는 `APPROVED` 상태이므로 자동 후보에 연결할 수 있다.
- 검수중 템플릿은 후보만 생성하고 실제 발송 버튼은 비활성화한다.
- 프라이빗 기간권 템플릿은 운영 보류 상태로 두고 자동 연결하지 않는다.
