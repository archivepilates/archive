# SOLAPI 템플릿 데이터 연결 운영 규칙

이 문서는 ARCHIVE IN에서 StudioMate/Firebase 데이터를 SOLAPI 카카오 알림톡 템플릿에 연결할 때의 운영 기준이다. 목적은 템플릿별 대상자 선정, 변수 매핑, 제외 조건, 중복 발송 방지를 한 기준으로 맞추는 것이다.

원본 정책 파일은 `firebase/kangsain-functions/functions/src/alimtalk/templatePolicies.ts`다. 이 문서와 Notion은 사람이 읽기 위한 뷰이며, 템플릿 ID, 상태, 대상/제외 조건, 반복금지 기준, 자동화 상태는 정책 파일을 기준으로 한다.

## 기본 원칙

- 알림톡 발송 기준 데이터는 `memberProfiles/{memberId}`를 중심으로 한다.
- 회원 식별은 이름이 아니라 `memberId` 우선, 보조로 `memberPhone`을 사용한다.
- Google 주소록은 보조 저장소이며 알림톡 대상자 원천으로 쓰지 않는다.
- 정산/매출/월간 분석용 엑셀 데이터는 알림톡 대상자 산정에 직접 쓰지 않는다.
- 수강권 기간/횟수 알림톡 대상자 원천은 `memberProfiles.activeTickets`다. 운영자 ACTIONS 날짜 목록은 화면 참고용이며 알림톡 대상자 선정 원천으로 쓰지 않는다.
- 템플릿 상태가 `APPROVED`가 아니면 실제 발송하지 않고 후보만 생성한다.
- 한 회원에게 같은 날 여러 후보가 생기면 신규회원, 프라이빗 사전설문, 잔여횟수, 잔여기간, 예약안내 순으로 우선순위를 둔다.
- 회원 연락처가 없거나 휴대폰 형식이 아니면 후보는 `skipped`로 기록하고 발송하지 않는다.
- 같은 회원에게 같은 사유의 알림을 반복 발송하지 않는다.
- 자동 발송은 매일 11:30 KST에 실행한다. 운영자가 직접 `queued`로 둔 후보는 큐 워커가 5분 주기로 처리한다.

## 수업/수강권 성격 판단 기준

- `lectures.lessonType`은 수업 자체가 그룹/프라이빗인지 판단하는 원천이다.
- `memberProfiles.activeTickets[].classType`은 회원이 보유한 수강권 성격을 판단하는 원천이다.
- `bookings.lessonType`은 예약 단위에서 수업 성격을 바로 확인하기 위한 캐시 필드다. 알림톡과 사전설문 로직은 `bookings.lessonType`을 먼저 사용한다.
- `bookings.ticketClassType`은 예약 수강권이 회원카드의 활성 수강권과 매칭될 때 저장하는 보조 필드다.
- `ticketName` 문자열 추정은 위 구조화 필드가 비어 있을 때만 사용하는 fallback이다. `순환`, `100회권`, 이벤트권처럼 이름만으로 그룹/프라이빗을 판단하기 어려운 수강권은 문자열 추정에 의존하지 않는다.

| `#{수강권명}` | `memberProfiles.activeTickets[].name` | 대상 수강권 1개만 선택한다. 여러 장이면 가장 먼저 만료/소진되는 수강권을 고른다. |

| `#{관리번호}` | 강사레슨 수업자료 관리번호 | 버튼 URL `https://in.archivepilates.com/method/#{관리번호}`에 사용한다. |

### 1. 신규회원 웰컴 안내

대상:

- StudioMate 회원 등록일이 확인된 신규회원.
- 기존 `memberProfiles`에 동일 `memberId` 기록이 없던 회원.
- 등록일 기준 3일 이내.
- 알림톡 자동 발송은 2026-05-16 이후 등록 회원부터 적용한다. 2026-05-15 이전 등록자는 backlog 발송하지 않는다.
- 신규회원 웰컴 후보는 발송 기준일 기준 등록 3일 이내 회원만 만든다. 3일이 지나면 후보 생성/자동 큐 전환 대상에서 제외한다.
- 활성 수업 수강권을 1개 이상 보유한 회원.
- 연락처가 정상 저장된 회원.

발송 시점:

- StudioMate 등록 감지 후 10분 이내 후보 생성.
- 매일 11:30 자동 발송 대상에 포함한다.

제외:

- 전화번호 없음.
- 활성 수업 수강권 없음. 상담고객처럼 회원 등록만 있고 수강권이 없는 경우는 제외.
- 체험권/그룹체험권만 보유한 회원. 체험권은 정규 수강권 안내 대상이 아니다.
- 강사레슨 수강권만 보유한 회원. 강사레슨은 강사/스탭 운영용 예외 수강권으로 보고 일반 회원 알림톡 대상에서 제외한다.
- 출산예정 등 운영자가 개별 예외로 지정한 회원.
- 기존 회원으로 확인됨.
- 이미 신규회원 웰컴 알림톡 발송 이력이 있음.
- 테스트/직원/미수금 등 운영 제외 태그가 있는 회원.

중복키:

- `new_member:{memberId}`

중복 방지 기간:

- 영구 1회. 같은 회원에게 신규회원 웰컴은 다시 보내지 않는다.

### 2. 그룹 기간권 잔여기간 안내

대상:

- 활성 그룹 기간권을 보유한 회원.
- 만료일까지 14일 이내.
- 이미 만료되지 않은 수강권.
- 같은 용도의 다른 활성 그룹 수강권을 보유하지 않은 회원.

발송 기준:

- `남은일수`가 `14, 7, 3, 1` 중 하나일 때 후보를 만들 수 있다.
- 초기 운영은 `14일 이내 최초 1회`만 발송한다.

제외:

- 다른 활성 그룹 수강권이 이미 있음.
- 수강권이 환불/사용불가/만료 상태.
- 회원이 프라이빗만 이용 중인 경우.
- 최근 7일 내 동일 수강권 만료 안내 발송 이력이 있음.

중복키:

- `group_period_expiring:{memberId}:{ticketId}:{expiresAt}`

중복 방지 기간:

- 30일. 같은 회원, 같은 템플릿, 같은 수강권으로 성공 발송된 이력이 최근 30일 안에 있으면 차단한다.

### 3. 그룹 횟수권 잔여횟수 안내

대상:

- 활성 그룹 횟수권을 보유한 회원.
- 잔여횟수 5회 미만, 즉 `1~4회`.
- 같은 용도의 다른 활성 그룹 수강권을 보유하지 않은 회원.

발송 기준:

- `잔여횟수`가 `4, 3, 2, 1` 중 하나일 때 후보를 만들 수 있다.
- 초기 운영은 `5회 미만 최초 1회`만 발송한다.

제외:

- 잔여횟수 0회.
- 다른 활성 그룹 수강권이 이미 있음.
- 기간권처럼 잔여횟수가 없는 상품.
- 수강권이 환불/사용불가/만료 상태.

중복키:

- `group_count_low:{memberId}:{ticketId}:{remainingCount}`

중복 방지 기간:

- 30일. 같은 회원, 같은 템플릿, 같은 수강권으로 성공 발송된 이력이 최근 30일 안에 있으면 차단한다.

### 4. 프라이빗 횟수권 잔여횟수 안내

대상:

- 활성 프라이빗 횟수권을 보유한 회원.
- 잔여횟수 3회 이하, 즉 `1~3회`.
- 프라이빗 수업 이용 이력이 있거나 예약이 있는 회원.

발송 기준:

- `잔여횟수`가 `3, 2, 1` 중 하나일 때 후보를 만들 수 있다.
- 초기 운영은 `3회 이하 최초 1회`만 발송한다.

제외:

- 잔여횟수 0회.
- 다른 활성 프라이빗 수강권이 이미 있음.
- 그룹권만 보유한 회원.
- 수강권이 환불/사용불가/만료 상태.

중복키:

- `private_count_low:{memberId}:{ticketId}:{remainingCount}`

중복 방지 기간:

- 30일. 같은 회원, 같은 템플릿, 같은 수강권으로 성공 발송된 이력이 최근 30일 안에 있으면 차단한다.

### 5. 프라이빗 사전설문 안내

대상:

- 프라이빗 수강권을 처음 등록한 회원.
- 또는 첫 프라이빗 예약이 생성된 회원.
- 설문 발송 이력이 없는 회원.

발송 시점:

- 프라이빗 수강권 등록 감지 후 후보 생성.
- 첫 프라이빗 수업 시작 전까지 발송하는 것을 원칙으로 한다.
- 현재 자동화는 예약 가능 기간 안의 첫 프라이빗 예약을 기준으로 후보를 만든다.
- 강사용 설문 전달 기준시각은 수업 하루 전 오전 9시다.
- 강사용 전달 기준시각까지 회원 설문 제출이 없으면 `home@archivepilates.com`으로 미제출 알림 메일을 1회 발송한다.

제외:

- 이미 설문 발송 이력 있음.
- 기존 프라이빗 이용 이력이 있음.
- 전화번호 없음.
- 프라이빗 수업이 취소되었고 향후 예약이 없음.

중복키:

- `private_survey:{memberId}`

중복 방지 기간:

- 영구 1회. 같은 회원에게 프라이빗 사전설문은 다시 보내지 않는다.
- 설문 응답 원본은 `privateSurveyResponses/{responseId}`를 최초 생성 1회만 허용한다. 같은 `responseId` 재제출은 중복으로 처리하고 강사용 알림톡/메모 큐를 다시 만들지 않는다.

### 5-1. 그룹 첫 수업 사전확인 안내

대상:

- ARCHIVE PILATES 그룹수업이 처음인 회원.
- 예약 가능 기간 안에 첫 그룹수업 예약이 있는 회원.
- 기존 그룹 사전확인 설문 제출 이력이 없는 회원.

발송 시점:

- 회원용 설문 요청은 첫 그룹수업 전 예약 기준으로 발송한다.
- 강사용 설문 전달 기준시각은 수업 시작 1시간 전이다.
- 강사용 전달 기준시각까지 회원 설문 제출이 없으면 `home@archivepilates.com`으로 미제출 알림 메일을 1회 발송한다.

중복 방지:

- `groupSurveyRequests/{requestId}`가 `submitted` 상태이면 설문 페이지와 API 모두 추가 제출을 받지 않는다.
- 설문 응답 원본은 `privateSurveyResponses/{responseId}`를 최초 생성 1회만 허용한다. 같은 `responseId` 재제출은 중복으로 처리하고 강사용 알림톡/메모 큐를 다시 만들지 않는다.

버튼 URL 제한:

- SOLAPI 버튼 URL은 변수 치환 후 100자 이하여야 한다.
- 함수는 원본 링크를 `shortLinks/{링크ID}`에 저장하고, 버튼에는 `https://in.archivepilates.com/s/#{링크ID}/` 형식의 짧은 링크를 넣는다.
- 회원용 그룹 설문 원본 URL은 `https://in.archivepilates.com/groupSurvey?id=#{설문ID}&token=#{접근토큰}` 형식이다.
- 강사용 설문 확인 원본 URL은 `https://in.archivepilates.com/privateSurveyResponseView?id=#{설문ID}&token=#{접근토큰}` 형식이다.
- 현재 승인 템플릿이 기존 변수 버튼을 쓰는 동안에는 원본 URL과 짧은 URL을 모두 검사한다.
- 짧은 링크 생성 전후에도 URL이 100자를 넘으면 ARCHIVE IN이 SOLAPI 발송 전에 차단한다.

### 6. 장기 미방문 수업안내

대상:

- 활성 수업 수강권을 보유한 회원.
- 회원목록 엑셀 `최근출석일` 또는 예약 출석 완료일 중 더 최신값이 발송 기준일로부터 10일 이상 지난 회원.
- 회원 연락처가 정상 저장된 회원.
- 마지막 출석일과 대상 수강권명이 확인되는 회원.

발송 시점:

- 매일 11:30 자동 후보 재계산 대상에 포함한다.
- 템플릿이 `APPROVED`가 되기 전에는 후보만 생성하고 실제 발송은 차단한다.

제외:

- 수강권 상태가 `정지중`, `중지`, `홀딩`인 회원. StudioMate 엑셀의 `수강권상태`를 `memberProfiles.ticketStatusSummary.hasHoldingTicket`으로 저장해 판단한다.
- 보호 스텝/강사 연락처.
- 1회권/1회상품권 등 일회성 수강권 보유 회원.
- 강사레슨 수강권 보유 회원.
- 발송 기준일 당일 또는 이후 예정 예약이 있음.
- 활성 수업 수강권 없음.
- 출석 완료 이력 없음.
- 마지막 출석 완료일이 10일 미만.
- 강사레슨 수강권 또는 수업권이 아닌 상품만 보유.
- 동일 회원의 같은 마지막 출석일 기준 장기 미방문 안내 발송 이력 있음.
- SOLAPI 미승인 템플릿.

중복키:

- `long_absence:{memberId}:{lastAttendanceDate}`

중복 방지 기간:

- 같은 회원의 같은 마지막 출석일 기준 1회. 새 출석이 발생해 `lastAttendanceDate`가 바뀐 뒤 다시 10일 이상 미방문이면 재판단한다.

### 7. 예약 안내

대상:

- 예약 오픈 안내가 필요한 활성 이용회원.
- 예약 가능한 수강권을 보유한 회원.
- 운영자가 지정한 예약 주차에 수업 예약이 필요한 회원.

발송 시점:

- 매주 예약 오픈 직전 또는 운영자가 지정한 시간.
- 예약 오픈 로직은 StudioMate 정책 변경 가능성이 있어 자동화 전 운영자 확인 단계를 둔다.

제외:

- 활성 수강권 없음.
- 휴면/장기 미방문으로 별도 케어가 먼저 필요한 회원.
- 최근 동일 예약주차 안내 발송 이력 있음.

중복키:

- `reservation_open:{memberId}:{reservationWeek}`

중복 방지 기간:

- 6일. 예약 오픈 안내는 주마다 반복될 수 있으므로 같은 내용은 한 주 안에서만 차단한다. `예약주차`가 바뀌면 다른 내용으로 본다.

### 8. 강사레슨 수업자료 안내

대상:

- 아카이브강사레슨 채널로 안내해야 하는 강사레슨 예약 회원.
- 수업명에 영문 주제명이 있는 예약. 예: `순환 circulation`.
- 관리번호는 `영문주제-수업날짜6자리` 형식으로 자동 생성한다. 예: `circulation-260526`.
- 회원 연락처가 정상 저장된 회원.

발송 시점:

- 기본은 수업 하루 전 11:30 자동 발송.
- 템플릿이 `APPROVED`가 아니거나 정책 파일의 `automationStatus`가 `paused`/`manual`이면 실제 발송하지 않는다.

버튼 URL:

- `수업자료 보기`
- `https://in.archivepilates.com/s/#{링크ID}/` 형식의 짧은 링크를 사용한다.
- 원본 자료 URL은 `https://in.archivepilates.com/method/#{관리번호}`이다.
- `방문안내 보기`
- `https://www.notion.so/367d49eae4bf811ca3daea273ed278c8`
- 버튼 URL은 변수 치환 후 100자 이하여야 한다. 현재 승인 템플릿이 기존 `관리번호` 버튼을 쓰는 동안에는 원본 자료 URL도 함께 검사한다.

제외:

- 관리번호가 비어 있는 예약.
- 수업명에서 영문 주제명을 추출할 수 없는 예약.
- 버튼 URL이 변수 치환 후 100자를 초과하는 예약.
- 강사레슨 예약이 취소된 회원.
- 같은 수업/관리번호 조합으로 이미 발송된 이력이 있는 회원.

중복키:

- `instructor_lesson_material:{memberId}:{lessonDate}:{managementNumber}`

중복 방지 기간:

- 영구 1회. 같은 회원, 같은 수업일, 같은 관리번호 조합으로 중복 발송하지 않는다.

### 9. 강사용 프라이빗 차트 작성 안내

대상:

- 다음날 프라이빗 또는 세미프라이빗 예약의 담당 강사.
- 강사 연락처가 정상 저장된 예약.
- 회차별 차트 요청 문서가 생성된 예약.

발송 시점:

- 수업 하루 전 18:00 이후.
- 템플릿이 `APPROVED`가 되기 전에는 후보를 만들더라도 실제 발송하지 않는다.

템플릿:

- `강사용_프라이빗 차트 작성 안내 v2`
- Template ID: `KA01TP260527182741301uIuSTL01YQ1`
- 메시지 타입: 일반 알림톡 `BA`
- 상태: `PENDING`

버튼 URL:

- `수업 전 계획 작성`: `https://in.archivepilates.com/s/#{수업전계획링크ID}/`
- `수업 후 기록 작성`: `https://in.archivepilates.com/s/#{수업후기록링크ID}/`
- `사진·영상 업로드`: `https://in.archivepilates.com/s/#{사진영상업로드링크ID}/`

데이터 매핑:

- `#{회원명}`: `privateLessonChartRequests.memberName`
- `#{회차}`: `privateLessonChartRequests.sessionNumber`
- `#{수업일시}`: 수업일 + 시작시간
- `#{수업전계획링크ID}`: 수업 전 계획 작성 short link id
- `#{수업후기록링크ID}`: 수업 후 기록 작성 short link id
- `#{사진영상업로드링크ID}`: 회차별 Notion 차트 페이지 short link id

운영 조건:

- SOLAPI는 버튼 URL 전체를 `#{수업전계획URL}`처럼 단독 변수로 넣는 방식을 유효한 URL로 인정하지 않는다. 버튼은 항상 `https://in.archivepilates.com/s/#{링크ID}/` 형식으로 등록한다.
- 3번째 버튼을 쓰기 위해 수업 하루 전 요청 생성 시점에 Notion 회차 차트 페이지를 미리 생성한다.
- Notion 회차 차트에는 사진·영상 업로드 섹션이 있어야 한다.
- 자동화는 Notion 페이지 갱신 시 기존 사진·영상 업로드 블록을 삭제하지 않는다.
- 회원에게 발송되는 최종 결과물은 Notion 페이지가 아니라 HTML 회원 리포트다.

## 후보 상태 운영

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| `candidate` | 규칙에 의해 생성된 후보 | 운영자 화면에 표시 |
| `reviewed` | 운영자가 확인했지만 아직 발송 전 | 발송 대기 또는 보류 선택 |
| `queued` | 발송 큐에 들어감 | 재시도/결과 대기 |
| `sent` | SOLAPI 발송 성공 | 발송 이력과 회원카드에 기록. ACTIONS에서는 완료 뱃지로 강조하지 않는다. |
| `skipped` | 제외 처리 | 사유를 기록하고 같은 조건 반복 노출 방지 |
| `failed` | 발송 실패 | 에러와 재시도 가능 여부 기록 |

## 발송 전 체크

자동 또는 버튼 발송 직전 아래 조건을 모두 통과해야 한다.

1. 템플릿 상태가 `APPROVED`이다.
2. 회원 연락처가 있고 휴대폰 번호로 정규화되어 있다.
3. StudioMate 동기화 데이터가 최신이다.
4. 같은 `dedupeKey`로 템플릿별 중복 방지 기간 안의 성공 발송 이력이 없다.
5. 대상 수강권이 아직 활성 상태다.
6. 다른 활성 수강권 보유로 제외되는 케이스가 아니다.
7. 운영자가 `skipped` 처리한 후보가 아니다.

## 우선순위

같은 회원에게 같은 날 여러 후보가 생성되면 아래 순서로 하나만 기본 추천한다.

1. 신규회원 웰컴
2. 프라이빗 사전설문
3. 프라이빗 잔여횟수
4. 그룹 잔여횟수
5. 그룹 잔여기간
6. 장기 미방문
7. 예약 안내
8. 강사레슨 수업자료 안내
9. 강사용 프라이빗 차트 작성 안내

운영자가 직접 선택하면 같은 날 여러 건을 발송할 수 있지만, 기본 자동 추천은 1건으로 제한한다.

## 자동 발송 스케줄

- `scheduledQueueAndSendAlimtalkDaily`: 매일 11:30 KST.
- 실행 시 `memberProfiles.activeTickets`를 직접 스캔해 발송 기준일의 수강권 상태를 재계산한다.
- 수강권 기간/횟수 안내는 발송 기준일 기준 만료 14일 이내, 그룹 잔여 5회 미만, 프라이빗 잔여 3회 이하 후보만 `queued`로 전환한다.
- 프라이빗 사전설문은 2026-05-19 이후 프라이빗 수강권 시작일이 발송 기준일과 같은 회원만 후보로 만든다. 기존 프라이빗 회원 전체에게 소급 발송하지 않는다.
- 장기 미방문 안내는 2026-05-24 이후 활성 수업 수강권 보유, 회원목록 엑셀 `최근출석일` 또는 예약 출석 완료일 중 더 최신값 기준 10일 이상, 보호 스텝/강사 연락처 제외, 1회권/강사레슨 수강권 제외, 수강권 정지/중지/홀딩 아님, 발송 기준일 당일 또는 이후 예정 예약 없음 조건으로 후보를 만든다. 현재 템플릿은 `APPROVED`이고 자동화 상태는 `active`다.
- 강사레슨 수업자료 안내는 발송 기준일 다음 날의 강사레슨 예약을 대상으로 만들며, 수업명에서 영문 주제명을 추출해 `영문주제-수업날짜6자리` 관리번호를 자동 생성한다.
- 운영자 ACTIONS에 생성된 과거/미래 날짜 후보는 알림톡 발송 원천으로 쓰지 않는다. 예전 대상일에 생성된 후보는 현재 수강권 상태와 맞지 않을 수 있으므로 자동 발송하지 않는다.
- 신규회원 웰컴은 발송 기준일 기준 등록 3일 이내 후보만 `queued`로 전환한다.
- 전환 후 큐를 즉시 처리한다. 잔여 `queued` 후보는 `scheduledProcessAlimtalkQueue`가 5분 주기로 이어서 처리한다.
- 후보 선정 단계에서 먼저 `memberId/memberPhone + templateCode + 발송범위` 기반 `dedupeKey`로 성공 발송 이력을 확인한다. 수강권 알림의 발송범위는 수강권명이고, 날짜별 남은일수/잔여횟수 변화는 같은 내용으로 본다.
- 중복이면 발송 가능 후보 ID에 넣지 않는다. 기존 후보 문서가 있거나 당일 리포트에 표시해야 하는 경우 `skipped`로 바꾸며 사유를 `중복 발송 차단`으로 남긴다.
- SOLAPI 발송 직전에도 같은 중복 검사를 다시 수행해 동시 실행이나 데이터 변경으로 인한 중복 발송을 차단한다.
- 템플릿별 중복 방지 기간은 예약 오픈 안내 6일, 수강권 기간/횟수 안내 30일, 장기 미방문 안내는 같은 회원의 같은 마지막 출석일 기준 영구 1회, 신규회원 웰컴/프라이빗 사전설문 영구 1회다.

## 운영자 화면 표시 기준

운영자 ACTIONS에는 단순히 "자동대상"으로 묶지 않고 아래처럼 사유를 분류해 보여준다.

- 신규회원
- 그룹 기간 임박
- 그룹 횟수 부족
- 프라이빗 횟수 부족
- 프라이빗 설문 필요
- 예약 안내 대상

각 후보 카드에는 `템플릿명`, `선정 이유`, `수강권명`, `남은일수/잔여횟수`, `최근 동기화 시각`, `발송/제외 버튼`을 표시한다.

## 현재 코드와 맞춰야 할 수정 포인트

- `rebuildAlimtalkCandidates.ts`의 템플릿 ID를 최신 승인 템플릿 기준으로 분기해야 한다.
- 그룹/프라이빗 수강권을 구분해 기간권과 횟수권 규칙을 따로 적용해야 한다.
- `ticket_expiring` 하나로 뭉친 후보를 `group_period_expiring`, `group_count_low`, `private_count_low`처럼 사유별로 분리해야 한다.
- 신규회원 웰컴 v3는 `APPROVED` 상태이므로 자동 후보에 연결할 수 있다.
- 검수중 템플릿은 후보만 생성하고 실제 발송 버튼은 비활성화한다.
- 프라이빗 기간권 템플릿은 운영 보류 상태로 두고 자동 연결하지 않는다.
