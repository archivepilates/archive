# ArchiveIN 테스트 계정 및 스모크 테스트 시나리오 초안

마지막 업데이트: 2026-05-14

## 1. 목적

이 문서는 ArchiveIN 배포 전후 최소 확인 항목을 정리한다. 목표는 앱 코드 변경 없이도 운영자가 실제로 쓰는 핵심 흐름이 살아 있는지 빠르게 판단하는 것이다.

검증 대상 URL:

- 우선 확인: `https://archive-pilates.web.app/archivein/`
- 레거시 리다이렉트 확인: `https://archive-pilates.web.app/kangsain/`
- GitHub Pages 확인이 필요한 경우: `https://archivepilates.github.io/archive/archivein/`

## 2. 테스트 계정 관리 기준

문서에는 비밀번호, 토큰, API key를 기록하지 않는다.

| 구분 | 계정 식별 | 권한/연결 | 용도 | 비고 |
| --- | --- | --- | --- | --- |
| 강사 테스트 계정 | Firebase Auth 이메일 계정 | `staffs/2222464` 정은영 강사 연결 | 강사용 수업 목록, 출결, 메모 스모크 테스트 | 비밀번호는 별도 안전 채널에서 관리 |
| 운영자 테스트 계정 | TBD | 운영자/ACTIONS 확인 권한 | ACTIONS 후보, 회원카드 깊이, 알림톡 연결 흐름 검증 | 운영자 권한 모델 확정 후 기입 |
| 읽기 전용 확인 계정 | TBD | 민감 정보 제한 | 모바일 표시/읽기 흐름 확인 | 필요 시 생성 |

테스트 계정을 만들거나 권한을 바꿀 때는 아래를 함께 기록한다.

- Firebase Auth uid 또는 안전한 내부 식별자
- 연결된 `staffs/{staffId}` 또는 운영자 권한 문서
- 접근 가능한 화면 범위
- 마지막 검증일
- 비밀번호 보관 위치는 문서에 쓰지 않고 별도 비밀 관리 절차로 남긴다.

## 3. 스모크 테스트 공통 준비

1. 배포 URL을 시크릿/프라이빗 브라우저에서 연다.
2. 모바일 실기기 또는 브라우저 모바일 viewport를 함께 준비한다.
3. 테스트 기준 날짜를 정한다.
4. 해당 날짜에 실제 수업이 없는 날인지 먼저 확인한다. 휴무나 공휴일로 비어 있는 상태는 버그로 보지 않는다.
5. PWA 또는 service worker 캐시가 의심되면 새 탭, 강제 새로고침, 버전 파라미터, Application cache 상태를 확인한다.

## 4. 강사용 핵심 스모크 테스트

### A. 로그인

절차:

1. `https://archive-pilates.web.app/archivein/` 접속.
2. 강사 테스트 계정 이메일/비밀번호로 로그인.
3. 로그인 후 강사 홈 화면으로 이동하는지 확인.

기대 결과:

- 로그인 화면의 앱 명칭은 아카이브IN/ARCHIVE IN 맥락을 유지한다.
- 로그인 실패 시 원인을 알 수 있는 실패 상태가 표시된다.
- 로그인 성공 후 새로고침해도 세션이 유지된다.

### B. 날짜 이동과 수업 목록

절차:

1. 오늘 날짜 수업 목록을 확인한다.
2. 전날/다음날로 이동한다.
3. 수업이 있는 날짜와 없는 날짜를 각각 확인한다.

기대 결과:

- 수업 시간은 Asia/Seoul 기준으로 표시된다.
- 수업 카드는 날짜 진입 시 기본 닫힘 상태다.
- 수업 헤더를 누르면 회원 목록이 펼쳐진다.
- 취소/대기취소 예약은 기본 목록에서 보이지 않는다.
- 예약대기 회원은 출석/결석 버튼이 비활성화된다.

### C. 그룹/프라이빗 표시

절차:

1. 그룹수업과 프라이빗 수업이 모두 있는 날짜를 연다.
2. 수업 카드의 타입 칩과 회원 정보 노출 범위를 확인한다.

기대 결과:

- 그룹/프라이빗 판단은 StudioMate 원본 수업 타입 기준과 맞아야 한다.
- 그룹수업 회원에게는 수강권명/잔여횟수를 기본 노출하지 않는다.
- 프라이빗 수업 회원에게는 수업 준비에 필요한 수강권 정보를 표시할 수 있다.

### D. 출결 처리

절차:

1. 수업 시작 시간이 지난 예약확정 회원을 선택한다.
2. 출석 또는 결석 처리 버튼을 누른다.
3. 화면 상태, pending/synced/failed 표시 여부를 확인한다.
4. 화면을 닫았다 다시 열어 상태가 유지되는지 확인한다.

기대 결과:

- 예약확정 회원이면서 수업 시작 이후인 경우에만 처리 가능하다.
- 입력 직후 화면에 반영되며, 서버 처리 상태가 사라지지 않는다.
- write queue 실패 시 운영자가 재확인할 수 있는 실패 상태가 남는다.

주의:

- 실제 StudioMate 쓰기 정책이 제한된 상태에서는 운영 환경에서 임의 회원의 출결을 바꾸지 않는다.
- 필요하면 테스트용 수업/회원 또는 사전 합의된 계정으로만 확인한다.

### E. 회원 메모와 태그

절차:

1. 회원 카드를 연다.
2. 건강 이슈, 최근 메모 요약, 자동 태그를 확인한다.
3. 테스트 메모를 작성한다.
4. 화면을 닫았다 다시 열어 메모가 유지되는지 확인한다.

기대 결과:

- 강사용 회원카드는 티칭에 필요한 건강/메모/최근 수업 맥락 중심이다.
- 운영자용 수준의 매출, 정산, 과도한 리스크 정보가 강사용 기본 화면에 노출되지 않는다.
- 메모 작성 상태는 optimistic 표시 후 서버 처리 결과와 일치해야 한다.

## 5. 운영자/ACTIONS 스모크 테스트

운영자 화면 또는 ACTIONS 기능이 배포된 경우 아래를 확인한다.

### A. ACTION 후보 품질

절차:

1. ACTIONS 목록을 연다.
2. 각 후보의 유형, 근거 데이터, 추천 조치, 대상 회원을 확인한다.
3. 중복 또는 조치 불가능 후보가 과도하게 뜨는지 확인한다.

기대 결과:

- 만료 임박, 잔여 부족, 장기 미방문, 출석 감소, 신규회원 케어, 상담 follow-up 등 조치 가능한 후보가 중심이다.
- 단순 통계나 의미 없는 경고가 ACTIONS 상단을 차지하지 않는다.
- 각 ACTION은 알림톡 또는 후속 처리로 이어질 수 있는 맥락을 가진다.

### B. 알림톡 연결 준비

절차:

1. ACTION 후보를 선택한다.
2. 발송 대상 확정 흐름이 있는지 확인한다.
3. 추천 메시지 템플릿, 개인화 맥락, 발송 기록 영역을 확인한다.

기대 결과:

- 기본 흐름은 자동 발송이 아니라 운영자 검토 후 발송이다.
- 발송 결과, 발송 시각, 템플릿, 대상 회원, 후속 상태를 남길 수 있어야 한다.
- 알림톡 자동화가 아직 연결 전이면 "준비/미연결" 상태를 명확히 보여준다.

### C. 운영자 회원카드

절차:

1. 운영자 권한으로 회원카드를 연다.
2. 강사용 화면과 다른 깊이의 정보가 보이는지 확인한다.

기대 결과:

- 연락처, 활성 수강권, 만료/잔여, 최근 30일 패턴, 리스크, 메모/후속 상태를 확인할 수 있다.
- 강사용 화면보다 넓은 운영 맥락을 제공한다.
- 민감 정보는 권한 없는 계정에서 보이지 않는다.

## 6. 데이터 동기화 스모크 테스트

### A. Firebase 캐시 확인

확인 항목:

- `instructorViews/{staffId}_{date}` 또는 해당 운영 뷰 문서 갱신 시각
- 화면 날짜와 Firestore 캐시 날짜가 일치하는지
- 화면 수업 수, 예약 수, 취소 숨김 처리 결과

기대 결과:

- 앱은 Firebase 캐시를 빠르게 읽는다.
- 캐시가 오래된 경우 화면 또는 운영 절차에서 갱신 상태를 확인할 수 있다.

### B. StudioMate 원천 확인

확인 항목:

- 수업/예약/출결 원천값
- 그룹/프라이빗 타입
- 회원 메모 원천

기대 결과:

- Firebase 캐시와 화면이 StudioMate 원천과 설명 가능한 차이만 가진다.
- 실시간 원천과 캐시 사이의 지연은 동기화 시각으로 설명 가능해야 한다.

### C. 아카이브DB 확인

확인 항목:

- 월별 유효회원, 정산성 지표, 운영 현황판 데이터
- Google Sheets `아카이브 DB` 갱신 시각
- Firestore dashboard 데이터마트 갱신 여부

기대 결과:

- 정산/월별 분석 지표는 StudioMate 실시간 API가 아니라 아카이브DB 기준임을 전제로 검증한다.
- 시트 갱신 지연과 Firebase 캐시 문제를 분리해서 판단한다.

### D. 맥미니 자동화 확인

확인 항목:

- 자동화 실행 여부
- 원본 엑셀/Drive 파일 생성 및 갱신 여부
- 아카이브DB 반영 여부

기대 결과:

- 맥미니 자동화 실패는 Firebase 앱 장애로 단정하지 않는다.
- 자동화 지연 시 어느 단계에서 멈췄는지 기록한다.

## 7. 모바일 UI 스모크 테스트

필수 viewport:

- iPhone Safari 실기기 또는 iPhone SE/14 계열 viewport
- Android Chrome 실기기 또는 Pixel 계열 viewport
- 데스크톱 Chrome

확인 항목:

- 로그인 폼이 화면 밖으로 밀리지 않는다.
- 날짜 이동, 수업 카드 펼침/접힘, 회원카드 열기/닫기가 터치로 자연스럽다.
- 태그, 이름, 상태 뱃지, 버튼이 겹치지 않는다.
- 하단 고정 버튼이나 플로팅 요소가 주요 버튼을 가리지 않는다.
- 메모 입력 중 키보드가 올라와도 저장 버튼을 누를 수 있다.
- service worker/PWA 캐시 때문에 이전 버전이 보이면 캐시 버전과 Hosting 헤더를 확인한다.

## 9. 현재 권한 스모크 테스트

2026-05-14 기준으로 Firebase SDK가 직접 호출하는 Callable Function은 Cloud Run Invoker IAM 체크를 서비스 단위로 해제해 둔다.

확인 대상:

- `loginstaffwithpin`
- `getinstructorhome`
- `submitbookingattendance`
- `submitmembermemo`
- `getmembermemohistory`
- `searchmembers`
- `registerfcmtoken`
- `setupstaffpinwithtempcode`
- `adminissuestafftempcode`
- `adminsynclecturesrange`
- `adminsyncmanagerstaffs`
- `adminpollmanagernotices`

간단 확인:

```bash
curl -i -X POST 'https://loginstaffwithpin-3bmxsf33jq-du.a.run.app' \
  -H 'Content-Type: application/json' \
  --data '{"data":{"phone":"test","pin":"0000"}}'
```

기대 결과:

- Cloud Run 레벨 `403 Forbidden`이 아니어야 한다.
- 테스트용 잘못된 입력이면 함수 내부의 `INVALID_ARGUMENT` 또는 앱 레벨 오류가 반환되는 것이 정상이다.
