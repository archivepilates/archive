# ARCHIVE CORE Current Site Wireframe

작성일: 2026-06-08  
대상: `https://core.archivepilates.com/`  
목적: ARCHIVE CORE UI/UX 업그레이드 전에 현재 사이트의 정보구조, 화면 패턴, 페이지별 섹션을 기준선으로 정리한다.

## 1. 제품 성격

ARCHIVE CORE는 강사용 앱이 아니라 ARCHIVE PILATES 운영자 전용 브라우저 콘솔이다.  
핵심 역할은 자동화, 원본 데이터, 회원 read-model, 알림톡, 프라이빗 차트, 경영 지표를 한 곳에서 확인하고 운영 판단을 빠르게 돕는 것이다.

현재 사이트의 UX 원칙:

- 직접 실행보다 `확인`, `판단`, `보호 규칙`을 우선한다.
- 외부 발송/쓰기 원천은 기존 canonical source를 유지한다.
- `members`, `member360Cards`, `dashboardSnapshots` 등은 판단용 read-model로 표시한다.
- 운영자가 다음에 볼 메뉴를 자연스럽게 이동할 수 있게 카드와 보드로 연결한다.

### Sidebar

현재 형태:

- 데스크톱에서 폭이 좁은 아이콘형 사이드바.
- 마우스 hover/focus 시 텍스트 라벨이 tooltip처럼 노출된다.
- 활성 메뉴는 accent 색상과 연한 배경으로 표시된다.

메뉴:

1. Home / 요약
2. Members / 회원
3. Lessons / 수업
4. Private / 차트

6. Automation / 관제
7. Business / 지표
8. Imports / 원본
9. Rules / 규칙

- `metric`: 핵심 숫자 카드
- `panel`: 기본 섹션 박스

## 4. Members

URL: `/members/`

역할: 회원 read-model을 검색하고 상세로 들어가는 운영자용 검토 화면.

```text
┌────────────────────────────────────────────────────────────────────┐
│ MEMBERS                                                            │
│ 회원 데이터                                                        │
│ 회원 기본정보, alias, 요약 read-model 분리                         │
│                                               [연결상태] [새로고침] │
└────────────────────────────────────────────────────────────────────┘

┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ 표시 회원    │ │ 활성 수강권  │ │ 최근 방문    │ │ 매출 요약    │
│ count        │ │ count        │ │ count        │ │ count        │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘

┌────────────────────────────────────────────────────────────────────┐
│ 전체 회원 요약                                                     │
│ [검색 input: 이름, 회원ID, 전화번호 끝자리, 수강권]                │
│ [전체] [활성] [최근 방문] [매출 있음] [품질 이슈]                  │
│                                                                    │
│ ┌────────────────────────────────────────────────────────────────┐ │
│ │ 회원              수강권              최근 방문       누적매출 │ │
│ │ ...                                                        ...  │ │
│ └────────────────────────────────────────────────────────────────┘ │
│ [pagination: 20명 단위]                                            │
└────────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────────┐
│ 회원 운영 보드                                                     │
│ 1. 검색/필터  2. 상세 확인  3. 품질 이슈  4. 외부 실행 stop        │
└────────────────────────────────────────────────────────────────────┘

│ members / memberAliases / memberSummaries / name-only match 금지   │

```

업그레이드 관점:

- 중복 회원은 목록에서 병합 표시하고 상세에서 alias/원천을 펼쳐 보여주는 구조가 적합하다.
- 현재 테이블은 운영 판단 정보가 부족할 수 있으므로 `상태`, `품질 신호`, `최근 액션` 컬럼 후보를 검토한다.
- 20명 페이지네이션은 유지하되 검색 결과 수와 현재 페이지 위치를 더 분명히 보여준다.

URL: `/private/`

역할: 프라이빗 차트 진행 상태를 강사/회차/단계별로 확인한다.

```text
┌────────────────────────────────────────────────────────────────────┐
│ PRIVATE                                                            │
│ 프라이빗 차트 진행                                                 │
│ 사전설문 → 수업후설문 → 리포트 완성 → 리포트 전송                  │
│                                               [연결상태] [새로고침] │

┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐

│ 기록 상태    │ │ 제출         │ │ 보정         │
```

- 앞으로 다른 탭도 Private의 4단계 보드처럼 `작업 상태 중심`으로 재편하면 좋다.
- 회차 표기는 `회원명 n회차 YYMMDD HH:mm 강사`처럼 짧고 동일한 포맷으로 통일한다.

현재 반응형 방향:

```text

│Sidebar │ │ 2~4 column cards / two-column panels          │
└────────┘ └──────────────────────────────────────────────┘

│Sidebar │ │ fewer columns / wider cards                   │
└────────┘ └──────────────────────────────────────────────┘

Mobile
┌─────────────────────────────────────────────────────────┐
│ Top/compact nav behavior                                │
├─────────────────────────────────────────────────────────┤
│ Header stacked                                          │
├─────────────────────────────────────────────────────────┤
│ KPI cards 1 column or compact 2 column depending content │
├─────────────────────────────────────────────────────────┤
│ Panels stack vertically                                 │
└─────────────────────────────────────────────────────────┘
```

업그레이드 시 필수 확인:

- 320px에서 가로 스크롤 없음
- tooltip/sidebar가 카드 뒤에 가려지지 않음
- 첫 번째 카드만 높이가 커지는 현상 없음
- KPI 카드 높이와 섹션 카드 높이 일관성
- 긴 한글/영문/수치가 카드 밖으로 넘치지 않음
- 회원 목록 페이지네이션과 검색 필터가 모바일에서 겹치지 않음
- Private 4단계 보드가 모바일에서 자연스럽게 세로 스택됨

## 15. Current UX Improvement Opportunities

우선순위 높은 개선 후보:

1. Home을 `오늘의 운영 우선순위` 중심으로 재설계한다.
2. Private의 4단계 진행 보드 패턴을 Messages, Automation, Imports에도 확장한다.
3. Members는 중복 회원을 병합 표시하고, 상세에서 alias/원천을 펼쳐 보여준다.
4. Lessons는 `오늘 문제 있는 수업`, `폐강/조정`, `예약/출석 이상`을 먼저 보여준다.
5. Business는 숫자 카드마다 비교 기준과 원본 상태를 더 명확히 표시한다.
6. Imports는 원본별 품질 이슈 원인을 바로 보여주는 root-cause 보드로 바꾼다.
7. Rules/Settings는 정적 설명보다 운영 링크와 최근 변경 상태를 보여주는 시스템 맵으로 바꾼다.

## 17. Design Notes

현재 디자인 톤:

- 밝은 운영 콘솔
- 좁은 icon sidebar
- 큰 카드 + pill 상태 라벨
- 주황 accent
- Apple system font 기반
- 둥근 모서리 8px 중심

업그레이드 시 유지할 점:

- 운영자 전용의 차분한 밀도
- read-only / canonical / guardrail 경계 표시
- 카드 기반 상태 요약
- 메뉴별 같은 정보 위계

업그레이드 시 줄일 점:

- 모든 섹션이 같은 카드처럼 보이는 단조로움
- 설명 문구가 많아 실제 숫자/액션이 묻히는 문제
- 정적 규칙 카드의 반복
- 페이지마다 다른 높이와 밀도의 카드 불균형
