작성일 2026-06-22 · 다음달 작업부터 수업 생성, 주제/기구 입력, 고정회원 예약을 한 세트로 묶어 실행합니다.

목표

한 번의 월간 작업으로 끝내기

월 그룹수업 생성, 주제·기구 입력, 고정회원 예약, 상세 검증, 결과 시트 기록을 하나의 운영 세트로 실행합니다.

교훈

화면 진입 실패와 예약 불가를 분리

일괄예약 카드가 보이지 않을 때는 수강권 문제로 단정하지 않고, 먼저 StudioMate 화면 진입과 셀렉터 상태를 검증합니다.

원칙

정확매칭만 실행

날짜, 시간, 강사가 모두 맞는 수업만 선택합니다. 가까운 시간이나 같은 주제 수업으로 대체하지 않습니다.

월간 실행 게이트

게이트 작업 통과 기준 실패 시 처리
0. 입력 확정 다음달 시간표, 주제/기구표, 고정회원 시트 확인 월, 강사, 요일, 시간, 전화번호, 시수 컬럼이 모두 존재 원본 시트에 입력오류로 남기고 쓰기 중단
1. 프리플라이트 StudioMate 로그인, 회원 검색, 일괄예약 화면, 수업카드 셀렉터, 수강권 상태 확인 샘플 회원 2명 이상에서 일괄예약 화면과 수업카드가 확인됨 surface_failed로 분리하고, 예약 안 된 회원은 수강권 만료·정지·횟수 사유를 함께 기록
2. 수업 생성 다음달 그룹수업 생성 월별 예상 수업 수와 생성 후 StudioMate 수업 수가 일치 중복·누락 수업만 따로 시트 기록 후 재시도
3. 주제·기구 입력 생성된 수업에 주차별 주제와 기구 입력 월 전체 수업의 제목/기구가 원본표와 일치 수업별 주제입력확인필요 기록
4. 고정회원 예약 회원 상세의 일괄예약 화면에서 정확매칭 카드 선택 예약 성공 메시지와 수업상세 예약회원 목록 둘 다 확인 메시지 성공이어도 상세 미반영이면 상세미반영으로 남김
5. 결과 검증 모든 대상 수업 상세를 다시 열어 예약회원 목록 확인 고정예약 시트 대상 전체가 완료 또는 사유 있는 실패 상태 이슈 건만 결과 탭에 남기고 성공 건은 숨김

다음달부터의 작업 순서

  1. 다음달 원본 시트 3개를 확정합니다: 시간표, 주제/기구표, 고정회원 리스트.
  2. npm run studiomate:monthly-preflight -- --month=YYYY-MM --source-sheet="N월 고정수업 리스트" --samples="김진선,심유정"로 읽기 전용 테스트를 먼저 실행합니다.
  3. 프리플라이트가 ready면 수업 생성 dry-run을 만들고, 중복 수업이 없을 때만 생성합니다.
  4. 수업 생성 후 주제·기구 입력을 적용하고, 생성된 수업 상세와 원본표를 대조합니다.
  5. 고정회원 예약은 회원별 일괄예약으로만 진행하고, 수업상세 예약회원 목록으로 후검증합니다.
  6. 예약 안 된 회원은 ticketStatus에 수강권 기간만료, 정지기간, 횟수/예약가능 0 여부를 같이 남깁니다.
  7. 결과 시트에는 실패/확인필요 건만 남깁니다. 성공 건은 요약 숫자로만 기록합니다.

상태값 표준

  • ready: 쓰기 전 샘플 검증 통과
  • surface_failed: 일괄예약 화면 진입 실패
  • exact_match_missing: 해당 날짜/시간/강사 카드 없음
  • exact_match_blocked: 카드 존재, 선택 불가 또는 정원마감
  • ticketStatus.issue: 예약 실패와 별도로 수강권 기간만료, 정지기간, 횟수/예약가능 0 같은 운영 사유가 확인됨
  • detail_not_reflected: StudioMate 성공 메시지 후 수업상세 미반영
  • completed: 수업상세 예약회원 목록에서 확인

백그라운드 단일 큐 운영

StudioMate 월간 작업은 여러 Codex 채팅에서 즉석으로 브라우저를 여는 방식보다 Mac mini 백그라운드 큐에서 직렬 실행하는 편이 안전합니다. 단, 회원 예약과 수업 생성은 운영 영향이 있으므로 승인 단계는 분리합니다.

단계 실행 방식 자동 실행 가능 여부 충돌 방지 장치
프리플라이트 백그라운드 read-only job 가능 공유 브라우저 lock, 시트 구조 검증, 일괄예약 화면 진입 검증
수업 생성 dry-run 백그라운드 plan 생성 가능 기존 수업 중복 검출, 예상 수업 수 대조
수업 생성 apply 승인 후 같은 큐에서 실행 승인 필요 월 단위 job id, 생성 전 재검증, 실패 시 중단
주제·기구 입력 apply 승인된 수업 생성 결과에 이어 실행 승인 필요 수업 id 기준 입력, 제목/기구 후검증
고정회원 예약 apply 승인 후 같은 큐에서 실행 승인 필요 회원별 일괄예약 직렬 처리, 성공 메시지와 수업상세 이중 검증
  • 큐 저장 위치는 ~/ArchiveIN/automation/monthly-studiomate/jobs/YYYY-MM.json로 고정합니다.
  • 작업 상태는 planned, preflight_passed, approval_required, applying, verified, attention_required로 관리합니다.
  • 백그라운드 job은 StudioMate 공유 브라우저 lock을 잡고 하나씩만 실행합니다.
  • 운영자가 승인하지 않은 상태에서는 StudioMate write 버튼을 누르지 않습니다.

재발 방지 규칙

  • 일괄예약 화면을 못 열었을 때는 회원 수강권 문제라고 쓰지 않습니다. 먼저 surface_failed로 기록합니다.
  • 자동화는 알림 피드 텍스트를 예약 화면으로 판정하지 않습니다.
  • 예약 성공 메시지는 충분 조건이 아닙니다. 최종 완료는 수업상세의 예약회원 목록으로만 확정합니다.
  • 월간 작업 중 StudioMate 공유 브라우저 프로필은 lock을 잡고 직렬 실행합니다.
  • 쓰기 작업 전에는 샘플 회원 2명 이상에서 일괄예약 카드와 정확매칭 결과를 확인해야 합니다.
