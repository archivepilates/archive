# 강사회원 가입서 주문 기준 연락처 검증

사용자가 주문서 연락처를 회원 연락처 기준으로 유지하도록 승인했다. 완료 가입서에 다른 번호가 작성돼 있어도 주문·등록·실제 회원·발송 문서·템플릿·실제 수신자·완료 상태가 모두 연결되는 경우에만 처리한다. 이름만 일치하거나 수신 번호가 마스킹/누락된 경우는 계속 차단한다.

## 범위와 보존

- `submittedProfile.memberPhone`는 작성된 번호를 유지한다. 여섯 입력 필드의 원문은 `rawFields`에 보존하고, `orderContactBinding`에 별도의 기준 연락처와 검증 원천을 기록한다.
- 회원 연락처를 수정하거나 서명된 문서를 고치지 않는다. 재발송도 하지 않는다.
- 주문 없는 기존 흐름과 연락처가 일치하는 기존 프로필은 종전 검증을 유지한다. 현재 주문 검증은 기존의 정상 결제·미래 수강일 조건을 유지하므로 과거 수강일의 예외 건은 자동 허용하지 않는다.
- 실제 회원 확인은 기존 StudioMate 브라우저 화면을 읽으며, 회원 편집 화면은 저장하지 않는다.
- 완료 트랜잭션 및 후속 메모 처리에서 최신 작업·등록 정보를 다시 대조한다. 문서 ID로 생성되는 기존 동의·메모의 중복 방지를 유지한다.

## 대상 지정 복구

`process-eformsign-instructor-member-jobs.mjs --apply --job-id <registration-id> --recheck-completed-document <document-id>`는 지정한 발송 완료 문서의 `send_review_required`만 선택한다. 완료 검사 분기로만 진입하며 발송 후보 생성, 전역 stale 복구, 다른 회원 처리를 하지 않는다. 이미 완료된 작업은 다시 처리하지 않는다.

처리 후 해당 가입서 작업, 동의 기록, 원문/기준 연락처 보존, 메모 job와 StudioMate 실제 반영, 등록 최종 상태를 각각 확인한다. 생년월일은 기존대로 빈 값 또는 동일 값만 허용하고 충돌 시 덮어쓰지 않는다.

## 검증

프로필 기존 회귀, 주문·문서·수신자·회원 불일치 차단, 원문 변조 차단, 실제 회원 편집 화면의 ID/연락처 검증, 대상 지정 복구의 재발송 차단 테스트를 실행한다. CI에 가입서 프로필/연결 검증 테스트를 추가한다. 운영 반영 전 실제 승인 대상에 읽기 전용 통합 검증을 시행한다.

이번 변경은 Mac mini 처리 스크립트이므로 main 승격 후 실행 저장소를 fast-forward 반영한다. Firebase Functions/Hosting 또는 권한·인증 설정을 변경하지 않는다.
