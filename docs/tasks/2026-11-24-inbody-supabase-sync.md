# 인바디 측정 결과의 회원별 Supabase 보관

- 원천은 LookinBody 상세 조회와 기존 Firestore 측정 이벤트 및 회원 카드입니다. 기존 이벤트와 추천식단·회원 리포트의 처리 상태는 이 작업에서 수정하지 않습니다.
- Supabase 회원 이력 프로젝트의 비공개 스키마에 측정 시각, 체중, 골격근량, 체지방률과 내부 연결 키만 보관합니다. 회원 키의 생성 방식은 검증된 StudioMate 회원 이력과 같습니다. 이벤트 키는 별도 용도로 생성합니다.
- 동일 지점에서 제공자의 ID·전화번호 전체·측정 시각이 알림과 일치하고, 해당 전화번호의 회원 카드가 하나뿐이며 이름·StudioMate 원본 회원 ID가 확인된 경우만 저장합니다. 여러 후보, 임시 번호, 상이한 회원명, 연결이 검증되지 않은 과거 기록은 보류합니다.
- 이벤트 키와 회원별 측정 시각에 각각 고유 제약을 둡니다. 동일한 값은 다시 저장하지 않고, 다른 값이 들어오면 덮어쓰지 않습니다. 비공개 저장소는 Supabase 프로젝트 관리자만 조회합니다. 전용 작업 계정은 검증 및 단건 저장 함수만 사용할 수 있습니다. 일반 앱·회원 이력 MCP·발송 작업은 이 데이터를 조회하거나 사용하지 않습니다.
- Supabase 보관 기간은 측정 시각부터 한국 기준 2년입니다. 데이터베이스에서 5분마다 만료분만 삭제합니다. 기존 LookinBody·Firebase 원본의 보관 규정은 별도입니다.
- 맥 미니 작업은 15분 주기로 최근 알림을 읽습니다. 원본 ID와 수치는 로그와 처리 상태 파일에 쓰지 않습니다. 일시적으로 실패했거나 회원 확인을 보류한 알림은 최근 조회 범위 안에서 재검토합니다. 누락 구간은 운영자가 원천 기간을 재검증한 후 처리합니다.

검증일 2026-11-24. 과거 상세 결과 19건 중 6건을 저장하고 13건을 보류했습니다. 11월 알림 50건에서 상세 조회와 회원 일치를 모두 확인한 37건을 새로 저장했습니다. 남은 13건은 회원 식별 근거 부족으로 보류했습니다. Supabase의 실제 레코드 43건에서 만료 시각을 대조했고 테스트용 데이터는 롤백했습니다.

운영 점검은 작업의 최신 집계 로그, 실제 Supabase 저장 건수·만료 작업 실행, 기존 서비스 권한의 차단을 순서대로 확인합니다. 사건 대응 시 신규 적재는 `com.archive.inbody-supabase`만 중지하면 되고, 2년 만료 작업은 별도로 유지합니다.
