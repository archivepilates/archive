# Member 360 DB

Decision date: 2026-05-28

## Decision

ARCHIVE IN keeps the existing feature-based Firestore collections as the source of truth, and adds a member-centered mirror database for CRM, app detail views, and GPT/business analysis.

Source of truth remains:

- `memberProfiles`
- `bookings`
- `memberMemos`
- `memberTags`
- `alimtalkCandidates`
- `alimtalkSends`
- StudioMate member ticket history normalized from member Excel plus member usage history

New derived data:

- `members/{memberId}`
- `members/{memberId}/summary/current`
- `members/{memberId}/tickets/{ticketId}`
- `members/{memberId}/purchases/{purchaseId}`
- `members/{memberId}/bookings/{bookingId}`
- `members/{memberId}/memos/{memoId}`
- `members/{memberId}/alimtalkLogs/{logId}`
- `members/{memberId}/tags/{tagId}`
- `member360Cards/{memberId}`

## Rules

- `members` and `member360Cards` are mirrors, not the source of truth.
- Existing source collections must not be overwritten by the mirror rebuild.
- `memberId` uses the existing ARCHIVE IN/StudioMate member id. Temporary `excel_...` ids remain valid until a real StudioMate id is resolved.
- Purchases must come from `member-ticket-history-normalized-*.csv`, not from the dashboard settlement Excel, because settlement Excel is name-only and unsafe for 동명이인.
- App and automation decisions should keep using source collections until `members` is verified and rules/UI are intentionally changed.
