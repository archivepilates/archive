  3. 회원 이벤트에 필요한 권한으로 심사 신청. 최소 권한만 요청하며 승인 여부는 아임웹이 결정.
  4. 승인 후 소유 사이트 연결과 연동완료 처리, 이벤트 수신 URL 등록.
  5. 샘플 전송과 실제 가입·등급 변경을 각각 검증한 뒤 운영 작업 전환.

일반 앱스토어 경로는 앱 테스트 → 승인 요청 → 제휴 계약·승인 → 앱스토어 게시 순서입니다. 자체 사이트용 웹훅의 게시 요건은 이 일반 경로와 구분하여 확인해야 합니다. 앱 생성·심사·게시 절차

2. 통일하는 40일 기준

적용 범위
강사레슨 출석자에게 복습 목적으로 부여하는 수강생 공유권. 식별 단위는 사이트 + 회원 + 승인된 수업/영상 묶음 + 권한 정책입니다. 같은 묶음의 두 영상은 하나의 시작 시각을 공유합니다.
시작과 종료
아임웹에 대상 그룹이 실제 반영되었음을 확인한 최초 시각을 고정합니다. 만료는 그 시각 + 40 × 24시간(960시간)이며, 해당 시각부터 만료 대상입니다. 수업일·회원가입일·처음 재생한 날이 아닙니다. 저장은 명시적 시간대가 있는 시각, 운영 표시는 한국시간을 사용합니다.
기간을 다시 시작하지 않는 경우
로그인, 재가입, 재점검, 중복 웹훅, 작업 재실행, 같은 그룹 재추가. 만료 후 같은 수업권이 자동 재발급되지 않게 종료 이력을 보존합니다. 재발급·연장은 별도 승인 건입니다.
기존 권한
최초 부여 증거가 있으면 그대로 유지합니다. 증거가 없거나 시각이 충돌하면 오늘부터 40일로 재설정하지 않고 확인 대상으로 둡니다. 과거 권한의 일괄 재산정·회수는 하지 않았습니다.
제외·보호
스텝 재직 중 전체 영상 접근은 40일 제한으로 바꾸지 않습니다. 별도 구매권·다른 팀 권한·관리자 권한·실물 할인도 바꾸지 않습니다. 수강생 공유 기간은 원래대로 만료하되 현재 스텝 또는 유효 구매로 같은 그룹이 필요한 경우 접근을 보존하고 원장에 사유를 기록합니다.

현재 E팀 실행 코드의 entitlementFromGrant는 이미 이 최초 확인 + 960시간 계산을 사용합니다. 이번 작업은 이를 공통 운영 기준으로 명확히 기록하는 단계이며, 다른 모든 과거 수업에 대한 실행 코드·원장 통합은 아직 하지 않았습니다.

현재 E팀 만료 작업은 정기 점검 때 회수하므로 만료시각과 실제 차단시각 사이에 지연이 생길 수 있습니다. 정확한 시각 차단이 필요하면 만료 예정 작업을 예약해야 하며, 웹훅만으로 시간 경과를 감지할 수는 없습니다.

3. 웹훅으로 대체할 것과 남길 것
