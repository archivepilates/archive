브라우저 경합을 발송 오류와 분리

홀딩 원본 조회마다 새 브라우저를 열던 경로를 한 회차의 전용 세션으로 통합했습니다. 잠금 경합은 발송 시도 없이 대기열에 남기며, 같은 회차의 다음 원본 검증도 캐시가 아닌 실제 화면을 다시 읽습니다.

확인한 원인

최근 운영 메일 3건은 원본 수집기의 공유 프로필 잠금 취득 실패였습니다. 이전 수집기는 대기 없이 실패하고 자동 실행기는 이를 일반 확인필요로 분류했습니다. 실제 잠금 소유 작업은 당시 기록만으로 확정하지 않았습니다.

부모 Excel 작업이 자신의 브라우저 잠금을 보유한 채 홀딩 자식을 실행하는 재진입 구조는 아닙니다. Excel 실행 락과 브라우저 프로필 락은 별개입니다.

수정 내용

  • 회차 단위 재사용: 기존 자동화 전용 프로필·공유 잠금을 한 번 취득해 브라우저를 재사용하고, 각 조회에는 새 페이지를 엽니다. 동시에 들어온 요청은 세션 안에서도 순서대로 처리합니다.
  • 잠금 대기: 최대 15초 대기한 후 busy 전용 오류로 분류합니다. 확정 이벤트를 만들기 전의 경합만 pending으로 넘기고 해당 회차를 멈춥니다.
  • 다음 실행 이월: 5·10·20·30분의 재조회 가능 시각을 기록합니다. 새 Excel에도 동일 회원·수강권의 대기를 보존하며, 실제 재시도는 기존 1시간 정기 실행에서만 합니다.
  • 알림: 연속 경합이 최초 발생부터 2시간 이상 지속될 때 내부 운영 알림을 보냅니다. 일반 원본 검증 오류·접수 불명확 경고는 이 유예 대상이 아닙니다.
  • 종료 안전: 중단·시간초과·조회 실패 시 브라우저 종료를 먼저 시도합니다. 종료를 확인하지 못하면 공유 잠금을 남겨 다른 작업의 동시 진입을 막습니다. Excel 결과 파일 기록 실패도 종료 정리를 건너뛰지 않습니다.
