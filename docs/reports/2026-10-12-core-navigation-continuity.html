변경 내용

메뉴 이동
로그인 후 메뉴·사용자 이름·로그아웃을 유지한 채 같은 출처의 다음 내용 화면을 준비합니다. 권한 확인과 본문 조회가 끝난 뒤 교체하며 이전 제목과 내용을 중복 표시하지 않습니다. 같은 브라우저의 Firebase 연결을 재사용하므로 메뉴마다 새 SDK·인증 클라이언트를 만들지 않습니다.
첫 접속
최초 접속·새로고침의 인증 및 서버 권한 확인은 생략하지 않습니다. 강사 화면 스타일과 서버 확인을 병렬로 진행합니다. 데이터 조회와 네트워크 대기는 남아 있으며 실제 통신 시간을 0으로 만들었다고 보고하지 않습니다.
시퀀스
이동 전에 기존 서버 저장 확인 루프를 실행합니다. 저장 실패·동시 수정 충돌이면 이동을 막습니다. 저장 성공과 새 화면 준비를 모두 확인한 뒤 이전 편집기를 닫아 브라우저 편집 잠금을 해제합니다. 저장본·UID·PDF·삭제 표식은 변경하지 않습니다.
접근 경계
각 새 화면에서 getCoreAccessSession을 다시 호출하고 UID·역할·담당자·첫 비밀번호 변경 상태를 확인합니다. 로컬 권한 캐시를 만들지 않습니다. 로그아웃·계정 변경·토큰 철회 시 준비 중·현재 내용 화면을 폐기하고 로그인 화면을 표시합니다. 뒤로·앞으로 이동도 새 화면 권한을 재검증합니다.
오류 처리
저장 확인 실패와 30초 화면 준비 지연 시 이전 본문을 보존하고 다시 이동할 수 있도록 안내합니다. 권한이 달라진 경우는 이전 권한으로 진행하지 않고 전체 접속을 다시 확인합니다.

발견 및 수정

  • 메뉴마다 독립 HTML·SDK·권한 게이트를 새로 시작하던 구조를 외곽 메뉴 유지 방식으로 변경했습니다.
  • 내용 화면에서 세션 해제 시 외곽 화면도 로그인 안내를 표시하도록 인증 변화 알림을 통일했습니다.
  • 기존 flex·grid 규칙이 hidden 표시를 덮어 이전 제목이 남던 문제를 명시적 숨김 규칙으로 수정했습니다.
  • 주소 전환 후 상대경로 메뉴가 다른 경로로 바뀌지 않도록 최초 메뉴 URL을 고정합니다.

범위 및 한계

Functions·Firestore 규칙·로그인 계정·비밀번호·회원·예약·알림톡·정산 자료는 변경하지 않았습니다. 신규 Firebase 시험 계정도 만들지 않았습니다. CORE 운영규칙에 변경 기준을 기록했습니다.

실제 iPhone Safari의 메모리·공유 동작과 실제 회원의 편집 중 이동은 합성 브라우저 검사만으로 확정하지 않습니다. 초기 권한 확인과 내용 조회 대기는 남습니다. 운영 라이브 파일 대조와 합성 검증은 실제 사용자의 체감 시간 측정과 구분합니다.

기존 의존성 설치에서 Node 22 권장 버전과 현재 Node 25의 차이 및 기존 보안 경고가 표시됐습니다. 이 화면 개선에 묶어 의존성을 무단 업그레이드하지 않았습니다.
