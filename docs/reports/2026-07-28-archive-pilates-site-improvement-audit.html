P0 · 먼저 고칠 것

효과가 크고 운영 위험이 낮은 항목입니다. 이 네 가지를 첫 작업 묶음으로 권합니다.

P0-1

홈 이미지를 홈에서만 불러오기

현재 아임웹 전역 스크립트의 preloadHomeImages()가 로그인, 상품 목록, 상품 상세까지 공식홈 이미지 6개를 모두 선로딩합니다.

  • 비홈 페이지에서 약 1.16MB의 불필요한 이미지 요청 제거
  • 홈에서는 오래된 archive-pilates.web.app 주소 6개를 직접 새 주소로 교체
  • 현재 홈에서 먼저 발생하는 404 요청 6개 제거
예상 효과모든 아임웹 페이지의 초기 전송량 감소
난이도 낮음 · 회귀 위험 낮음
P0-2

품절 상태와 “강사레슨 예약” 문구 맞추기

공식홈의 “강사레슨 예약”은 /offline을 거쳐 현재 “7월마감 · SOLDOUT” 상품 한 개가 있는 화면으로 연결됩니다.

  • 마감 중에는 “다음 강사레슨 알림 신청” 또는 “강사레슨 일정 확인”으로 변경
  • 카카오 문의가 아니라 이름·연락처를 남기는 대기신청 흐름을 우선 제공
  • 다음 일정이 열리면 다시 “예약”으로 전환
예상 효과클릭 후 실망 감소
마감 수요를 다음 회차로 축적
P0-3

구형 /studio와 빈 /15 검색 노출 정리

아임웹 사이트맵에는 65개 URL이 있으며, 구형 스튜디오 페이지와 내용이 없는 페이지도 포함됩니다. /studio에는 현재 방향과 다른 “1:1 · 듀엣 · 3~4인 일반회원 수업” 문구가 남아 있습니다.

  • /studio는 공식홈 철학 섹션으로 영구 이동하거나 검색 제외
  • /15는 삭제 또는 검색 제외
  • 아임웹 홈 /index도 브랜드 검색 경쟁을 피하려면 검색 제외 검토
예상 효과공식홈 검색 집중
오래된 브랜드 설명 제거
P0-4

데스크톱 상품 목록을 더 촘촘하게

판매상품 목록은 현재 1440px 화면에서도 카드 폭이 625px인 2열입니다. 27개 상품이 약 7,300px 이상 이어져 비교와 탐색이 느립니다.

  • 니티도: 데스크톱 4열 · 태블릿 3열 · 모바일 2열
  • 온라인 영상: 데스크톱 3열 · 태블릿 2열 · 모바일 2열
  • 목록 상단에 “판매상품” 또는 “온라인 클래스” 제목과 상품 수 표시
예상 효과한 화면 비교량 2배
페이지 길이 약 40~50% 감소

P1 · 구조를 안정화할 것

P0 이후에 진행할 중간 규모 개선입니다. 과거 패치가 다시 충돌하지 않게 만드는 작업이 중심입니다.

P1-1

28개 전역 커스텀 스크립트를 하나의 런타임으로 통합

라이브 HTML에서 ARCHIVE 커스텀 스크립트 마커 28개가 확인됩니다. 헤더, 모바일 안전영역, 메뉴, 내 강의실, 홈 이미지, 니티도, 관심상품 패치가 서로 다른 시점에 DOM을 다시 만집니다.

  • 작은 인라인 로더 1개 + 버전된 외부 런타임 1개로 통합
  • home, shop, video, classroom, product-detail 모듈을 경로별 실행
  • 구버전 마커와 중복 MutationObserver 제거
  • 현재 정상인 헤더 스크롤, 니티도 이동, 관심상품, 내 강의실을 회귀 테스트한 뒤 교체
예상 효과헤더 떨림 재발 방지
다음 수정 속도 향상
난이도 중상
P1-2

니티도 목록 이미지 전달량 줄이기

Lighthouse는 판매상품 목록에서 이미지 약 3.2MB를 줄일 수 있다고 추정했습니다. 321px로 보이는 카드에 750~800px JPG가 전달되는 사례가 반복됩니다.

  • 목록용 480~600px WebP와 상세용 원본을 분리
  • 아임웹 CDN이 허용하면 목록 URL 크기 파라미터를 480~600으로 조정
  • 첫 행만 우선 로드하고 나머지는 현재처럼 lazy load 유지
예상 효과모바일 데이터 절감
목록 LCP 개선
상품 사진 선명도 유지
P1-3

상품 상세의 미리보기를 클릭 후 로드

온라인 상품 상세는 유튜브·네이버 플레이어 코드까지 초기에 불러옵니다. 미리보기 두 블록도 시각적으로 중복되어 상세페이지가 길어집니다.

  • 정적 포스터 1개를 먼저 표시하고 재생 시 iframe 생성
  • 대표 미리보기 한 개만 상단에 유지
  • 나머지는 “수업 구성” 아래 챕터 이미지로 전환
예상 효과초기 JS·쿠키·네트워크 감소
상세페이지 집중도 향상
P1-4

접근성 기본값 보완

공식홈은 Lighthouse 접근성 100점이지만 아임웹은 목록 83점, 상품 상세 75점입니다.

  • 햄버거·공유·빈 링크에 접근 가능한 이름 추가
  • 장바구니·검색·로그인·나가기 터치 영역을 최소 44×44px로 확대
  • 온라인 카테고리 활성 색상 대비 개선
  • 가능하면 확대를 막는 user-scalable=no 제거
예상 효과모바일 오조작 감소
키보드·보조기기 이용성 개선
P1-5

기구별 카테고리 SEO를 고유하게

/44~/47은 정상 상품 목록이지만 페이지 제목이 모두 “아카이브필라테스”이고 H1이 없습니다. 상품 목록 이미지도 대부분 빈 alt입니다.

  • “리포머 온라인 클래스 | 아카이브필라테스”처럼 고유 title·description·H1 적용
  • 상품 이미지 alt를 상품명으로 채우기
  • 실제 구매평이 생긴 뒤에만 review·aggregateRating 구조화 데이터 사용
예상 효과기구명 장기 검색 유입
이미지 검색·접근성 개선

P2 · 성장 단계 개선

현재 기능을 건드리지 않고 브랜드 품질과 운영 측정력을 높이는 작업입니다.

P2-1

공식홈 반응형 이미지 세트

공식홈은 이미 빠르지만 Lighthouse가 약 417KB의 이미지 절감 여지를 찾았습니다. hero 재압축, AVIF/WebP, srcset을 적용하면 모바일 LCP를 더 낮출 수 있습니다.

예상 효과공식홈 성능 80점대 후반 기대
브랜드 화면은 그대로 유지
P2-2

팀아카이브 이미지와 전환 연결

팀 페이지 첫 방문은 좋지만 전체 팀 사진이 약 1.2MB입니다. 카드용 WebP를 따로 만들고, 강사별 프로필에서 해당 강사의 강사레슨 또는 관련 영상으로 연결하면 소개가 구매까지 이어집니다.

예상 효과팀 페이지 로드 절감
프로필의 전환 기여도 향상
P2-3

공식홈에서 아임웹까지 전환 측정

“강사레슨 예약”, “영상구매”, “판매상품”, “팀아카이브” 클릭을 이벤트로 기록하고 아임웹 주문 데이터와 주 단위로 비교합니다. 새 디자인보다 먼저 어느 경로가 실제 구매로 이어지는지 알 수 있습니다.

예상 효과개선 우선순위를 감이 아닌 데이터로 결정
P2-4

구매자 시청 접근 스모크 테스트 정례화

공개 상태에서는 /48이 로그인으로 정상 이동했습니다. 다만 이번 진단은 주문을 만들지 않았으므로 비회원·미구매 회원·구매회원 전체 권한 검증은 별도 테스트 계정으로 정례화해야 합니다.

예상 효과상품 추가 후 “내 강의실에 안 보임” 재발 방지

지금 잘되는 부분

아래는 유지해야 할 기준입니다. 개선 작업이 이 동작을 되돌리면 안 됩니다.

공식홈 검색 기반

루트 200, canonical, robots, sitemap, 지역 사업 구조화 데이터가 정상입니다. www는 루트로 301 이동합니다.

공식홈 품질

320·390·768·1440px에서 가로 넘침이 없고 Lighthouse 접근성·권장사항·SEO가 모두 100점입니다.

메뉴와 하위 카테고리

공식홈 주요 링크가 모두 살아 있고, 아임웹 온라인 기구 메뉴는 스크롤 시 안정적으로 상단에 고정됩니다.

니티도 브랜드 페이지

브랜드 소개, H1, 단체 사진, 아카이브 관점의 글과 제품 연결이 일관되고 완성도가 높습니다.

상품 상세의 필수 고지

40일 이용, 회원그룹 권한, 환불 기준, 구매 버튼이 한 페이지에 존재하고 상품별 canonical도 정상입니다.

내 강의실 공개 차단

로그아웃 상태에서 /48은 로그인 화면으로 이동해 공개 노출되지 않습니다.
