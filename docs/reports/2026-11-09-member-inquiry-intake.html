5. 규정 판단과 실행 가능 여부를 따로 봅니다

예외·규정 충돌·자료 부족
자동 거절하지 않고 검토 사유와 추가 질문을 제시합니다. 관리자가 예외 범위와 사유를 결정하고 수동 처리합니다.
현재 MCP 확인: 기존 재등록 상담 건의 상태 저장, 홀딩 안내 승인·진행 조회는 있습니다. 일반 수업 예약·취소·홀딩 적용·전환의 범용 실행 기능은 현재 카탈로그에서 지원되지 않습니다. 직원 접수함 생성·배정·판정 기능도 새로 필요합니다.
AI는 문의 요약·분류·답변 초안을 돕고, 가능 여부는 버전이 고정된 규정과 원본 값으로 판단합니다. 자유 입력이나 문서 안의 지시가 실행 권한을 만들지 않습니다.

  • 승인은 정확한 변경안에 묶기: 수강권·예약 ID, 날짜, 변경 전후, 규정 버전, 영향받는 기존 예약, 비용과 안내문을 함께 확인합니다. 요청·원본·규정이 바뀌거나 승인 계획이 만료되면 다시 승인합니다.

  • 중복·결과불명: 문의번호와 원본 회원·예약/수강권·행위에 대한 고정 키로 중복을 막습니다. 접수 결과가 불명확하면 기존 건을 먼저 조회하고 재실행하지 않습니다. 이미 수동 처리된 건도 재조회 후 종료합니다.
  • 수업 변경: 새 수업 확보 실패 시 기존 예약을 먼저 취소하지 않습니다. 두 단계 변경의 부분 실패는 보상 가능한 범위와 담당자 확인으로 복구하며 성공으로 표시하지 않습니다.
  • 최소한의 개인정보: 내부 알림에는 접수번호·유형·기한·보안 상세링크만 전달합니다. 전체 연락처·증빙·건강 사유를 메신저로 복제하지 않습니다. 담당자별 접근과 수집·보존 기준을 출시 전 확정합니다.
