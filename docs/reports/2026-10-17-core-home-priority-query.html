홈 ‘오늘 우선순위’ 조회 오류

수정·운영 배포·라이브 검증 완료
회원 데이터 손상이 아니라, 메뉴 전환 후 공유 Firebase 연결의 조회 조건 전달 오류였습니다. 기존 자동발송·중복방지는 변경하지 않았습니다.

확인한 현상

홈을 직접 열면 조회가 완료됩니다. 다른 메뉴를 거쳐 홈으로 돌아오면 알림톡 후보·발송·기존 웰컴·가입서·수강료 안내의 미해결 상태 조회 5개가 실패합니다. 화면에는 동일한 오류 문구가 반복되고 ‘업무 조회 확인 필요’가 표시됩니다.

원인

메뉴의 내부 화면에서 만든 상태 목록을 상위 화면의 Firebase SDK로 전달할 때, Firebase 10.14.1이 다른 화면의 배열을 일반 배열로 인식하지 못합니다. 실제 경고는 Unsupported field value: a custom Array object입니다.

수정

  • Firebase 연결을 소유한 화면에서 상태·회원 ID 목록을 복사한 뒤 동일한 조회 조건으로 전달합니다.
  • 조회 오류는 ‘알림톡 대기·실패’, ‘알림톡 발송 결과’, ‘가입서 후속 처리’ 등 원천별로 구분합니다.
  • 회원 원본, 승인·중복 차단, 대상 선정, 알림톡 발송과 정기 자동화는 변경하지 않습니다.

검증 결과

실제 Firebase SDK의 네트워크 없는 조회 생성에서 기존 오류와 수정 결과를 대조했습니다. 조회·홈·재등록·메뉴 이동·템플릿 목록 회귀 55건 통과, Hosting 검증·롤백 안전검사·변경분 공백 검사도 통과했습니다.

합성 데이터 전체 화면 테스트는 320·390·768·1440px, 기본 주소와 /core/ 주소의 8조합 모두 통과했습니다. 메뉴를 이동한 뒤 돌아온 내부 홈에서도 5개 원천 조회와 정상 표시를 확인했습니다. 첫 실행에서 테스트 도구의 예전 관리자 탭 명칭을 수정한 뒤 전 조합을 재검증했습니다. 실제 사용자 자료는 변경하지 않았으며 테스트 브라우저·서버·컨텍스트와 별도 운영 점검 탭을 모두 정리했습니다.

운영 반영

2026.10.17 사용자 승인 후 2b0d8070을 main에 반영·푸시하고 기존 서비스 계정으로 CORE Hosting 두 주소에 배포했습니다. 회원 데이터·Functions·Firestore 규칙·자동화 주기는 변경하지 않았습니다. 운영규칙도 같은 릴리스에 포함했습니다.

  • 배포 전후 반응형 검사: 각 95건 통과.
  • 배포 식별자: 두 주소 모두 소스 커밋 일치. 앱·조회 보완 모듈·템플릿 목록·운영규칙의 해시 8개 일치.
  • 실제 운영자 로그인 검증: 홈 직접 접속 → 알림톡 메뉴 → 홈 복귀 모두 조회 완료. 복귀 후 오류·경고 로그 없음.
  • 홈 표시값은 직접 접속과 복귀 모두 ‘9건 확인 필요’로 일치했습니다. 재등록 전체 대상 적합성까지 재감사한 결과는 아닙니다.
  • GitHub Actions 38997003303 성공.

기존에 열어둔 사이트는 전체 새로고침 한 번이 필요합니다. 메뉴 안의 새로고침만으로는 예전 상위 연결 코드가 교체되지 않습니다. 점검용 브라우저만 정리하고 기존 사용자 탭은 보존했습니다.

별도 점검 사항

합성 데이터 검토에서 오래된 원천의 정상 판정, 재등록 후보의 저장된 긴급도, 대기·실패 중복 집계, 테스트 대기 후보 포함, 자동화 상태 조회 한도에 대한 추가 보완 후보가 발견됐습니다. 실제 운영 영향과 정책을 대조하지 않았으므로 이 수정으로 해결됐다고 보고하지 않습니다.
