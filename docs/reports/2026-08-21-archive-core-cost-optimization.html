읽기량 판단

변경 전 홈은 코드상 의도된 상한만 합쳐도 약 6,947건이었고, 일부 공통 조회는 서버 제한이 없어 실제로는 컬렉션 전체를 읽을 수 있었습니다. 변경 후 정상 조회 경로의 최댓값은 재등록 장부 1,000건과 해당 후보 회원 원본 최대 1,000건을 포함해 약 2,263건입니다. 실제 재등록 후보가 적으면 이보다 더 낮습니다.

  • 단순히 명령창을 열거나 업무 메뉴를 검색할 때는 회원 디렉터리를 읽지 않습니다.
  • 회원명·전화번호 검색이 필요할 때만 회원 요약과 원본을 각각 최대 2,000건 읽고 현재 페이지에서 한 번 재사용합니다.
  • 재등록 최신성 검증은 없애지 않고, 재등록 장부에 연결된 canonical memberProfiles만 조회합니다.

  • CORE Hosting guard, GCP 비용 guard, 데이터 원천 정책, 라이브 롤백 guard 통과
  • 재등록 17개, 프라이빗 흐름 22개 테스트 통과

  • Firebase Hosting 로컬 에뮬레이터 확인: HTML no-store, JS/CSS 재검증, 이미지 1시간 캐시 헤더 적용

배포 주의

현재 변경은 운영에 배포하지 않았고 GitHub에도 올리지 않았습니다.

  • firebase.json 변경 때문에 일반 affected 감지는 모든 Functions 코드베이스를 선택합니다.
  • 실제 반영 시 Hosting은 archive-pilates-core, Functions는 functions-alimtalk·functions-private-chart·functions-sync만 명시적으로 분리해야 합니다.
  • 배포 후 실제 CORE 응답 헤더, 세 Scheduler의 10분 주기, Firestore 일일 읽기, CORE Hosting 전송량을 다시 확인해야 합니다.
  • 직접 결제액 절감은 무료 구간과 실제 접속량에 따라 달라지므로 고정 금액으로 단정하지 않고 배포 후 72시간 데이터를 비교합니다.
