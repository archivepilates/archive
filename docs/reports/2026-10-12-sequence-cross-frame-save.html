시퀀스 저장 오류

2026-10-12 · 모바일 메뉴 이동

원인

메뉴 전환 화면은 상위 화면의 Firebase 연결을 재사용합니다. 이때 하위 화면에서 만든 저장 객체를 상위 Firebase SDK가 일반 객체로 인정하지 못해 저장이 거부됩니다. 메뉴 이동 보호가 이 저장 실패를 감지해 작성 화면을 유지한 상태입니다.

수정 범위

  • 본문·사진·삭제 표식의 최상위 쓰기 객체를 화면 실행 환경에 종속되지 않는 형식으로 만듭니다.
  • 서버 시각·작성일·UID·버전 비교·삭제 표식은 보존합니다. JSON 변환으로 Firebase 시각 값을 없애지 않습니다.
  • 저장 실패 화면에서 작성 내용 백업을 바로 내려받을 수 있도록 합니다. 백업은 서버 저장 완료가 아니며 자동 복원하지 않습니다.
  • 저장 실패·충돌 시 메뉴 이동 차단은 그대로 유지합니다.

현재 입력 보존

스크린샷에 나온 노트 ID는 서버에 없었습니다. 화면을 닫거나 새로고침하기 전에 기존 화면의 미리보기 → 파일·인쇄 → 응답 파일 저장으로 백업하세요. 미리보기에는 수업명과 이름을 입력한 동작이 하나 이상 필요합니다. 미완성 입력은 먼저 복사하거나 화면을 보관하세요. 수정 반영 후 응답 불러오기는 새 사본으로 저장하며 기존 노트를 덮지 않습니다.

실제 사용자 문서·사진·권한은 변경하지 않았습니다. 이 보고서에는 시퀀스 원문이나 소유자 식별값을 보관하지 않습니다.

검증

메뉴 이동 단위검사 5건, 강사·프라이빗 접근 회귀 224건, 기존 시퀀스 작성·저장·PDF·삭제 회귀 26건, 서로 다른 실행 환경의 저장 검사 24건 및 Hosting·롤백 방어를 통과했습니다. 실제 Firebase 10.14.1 파서로 Chromium·WebKit의 320·390·768·1440px 화면에서 16건을 통과했고 메인 작업에서 재검증했습니다. 수정 전 본문·사진·삭제 표식 오류를 재현하고 수정 후 시각 값 보존·백업·재시도·저장 확인 후 이동을 확인했습니다. 독립 코드 리뷰에서도 수정할 문제를 찾지 못했습니다.

브라우저 테스트는 실제 편집기와 저장 코드를 사용하지만 저장 데이터와 로그인은 격리 합성 환경이며, 메뉴 이동은 축소 검증 화면입니다. 실제 회원 데이터·운영 쓰기·인증된 CORE 전체 화면·Firestore 보안 규칙 검증은 하지 않았습니다. 실제 iPhone 기기는 별도 확인 대상입니다. 테스트 브라우저·서버는 모두 종료했습니다.
