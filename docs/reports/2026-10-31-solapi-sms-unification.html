일반 문자 SOLAPI 통합

ARCHIVE PILATES OPS · 2026-10-31

승인된 범위

직접 작성하는 SMS·LMS·MMS는 SOLAPI를 사용합니다. 기존 세 경로인 강사회원 가입서 미작성 안내, 일반회원 서명 안내, 환불 예상금액 안내의 발송 부분을 교체합니다. 기존 영상 안내 LMS·알림톡은 SOLAPI를 유지합니다.

StudioMate·이폼싸인 자체 계약 초대 문자는 별도 보안·서명 기능이므로 유지합니다. 과거 미발송 건 수동 일괄 처리·시험 문자·작업 초기화·새 자동화는 승인 범위에 없으며 실행하지 않습니다.

유지하는 안전장치

  • 기존 원본·가입서·회원·수강권·취소·환불 검증과 정본 업무 키·승인·공용 잠금을 유지합니다.
  • 기존 StudioMate 접수·불명확 시도는 그대로 보존해 SOLAPI로 바뀌어도 재발송하지 않습니다. 제공자 이력은 SMS/LMS/MMS를 함께 대조합니다.
  • 일반 문자 09:00~22:59, 서명 미작성 안내 09:00~19:59를 실제 POST 직전까지 확인합니다. 원본 확인 후 단일 선점과 1회 요청만 허용하며 POST는 재시도하지 않습니다.
  • 접수 ID와 그룹 ID·실제 전송 문구/수신자 해시를 원래 작업에 저장하고 최종 전달은 별도입니다. 결과 불명은 보류하며 다른 발송 경로로 우회하지 않습니다.

연결 검증

현재 SOLAPI 등록번호 두 개 중 기존 승인 문자와 일치한 번호(끝자리 4425)를 전용 비공개 설정에 고정했습니다. 비밀 키는 기존 Secret Manager에서 읽으며 저장·출력하지 않습니다. LaunchAgent의 제한된 PATH에서도 설정과 인증값 로드 후 의도적인 무발송 중단을 확인했습니다.

현재 미작성 작업의 제공자 읽기 전용 사전 점검은 2026-10-31 10:47 KST에 원본 재검증 직전 중단 지점까지 도달했습니다. 제공자 GET 2회, POST 0회, 정본 쓰기 0회, 실제 문자 0건입니다. 이는 실제 접수·전달 증거가 아닙니다.

검증·배포 상태

무발송 회귀검증 1,652건 통과 · 운영 문자 경로와 CORE 규칙 반영

전송 계층·두 안내 처리기·환불 검증·기존 원본 식별·공용 HMAC·릴리스 가드와 CORE 화면 검증을 합친 수치입니다. 새 규칙은 320/390/768/1440에서 텍스트 넘침 없이 확인했고 작업 소유 브라우저를 종료했습니다. 발견한 시간 경계·잘못된 접수증·유형별 이력 누락·실제 제목 해시·그룹 ID만 남은 보류 기록 문제도 배포 전에 수정했습니다.

구현 커밋 41943bd3을 main에 푸시하고 운영 실행기에 반영했습니다. 10:48 KST CORE 규칙만 배포했으며 10:49 독립 조회에서 두 운영 주소 HTTP 200, 원본 해시 일치, 63개 경로 중 규칙 파일 하나만 변경됨을 확인했습니다. 배포 버전: 094582bfbc5d0249.

기존 주기·큐는 유지합니다. Functions 소스는 바꾸지 않았으며, CI 워크플로 변경 때문에 보수적 영향 감지는 다섯 코드베이스를 표시합니다. 실제 배포는 맥미니 런타임과 CORE 운영규칙 한 파일뿐입니다.

Functions 검사 통과. 최초 MCP 검사는 기능·화면 검증을 통과했으나 하위 패키지의 중간 위험도 취약점 6건으로 실패했습니다. 직접 SDK 버전은 유지하고 glob·minimatch만 패치해 로컬 252개 테스트와 취약점 0건을 확인했습니다. 기존 rimraf 정리 동작 호환 테스트는 통과했지만 전체 사용 경로의 완전한 호환 증명은 아닙니다. 후속 CI·운영 MCP 검증은 최종 증거로 구분해 기록합니다.

별도 기존 한계: member-dispatch-macmini의 이폼싸인 합성 fixture 실패 4개는 수정 전 런타임에서도 재현됩니다. 전체 Hosting 묶음의 기존 카탈로그 해시 불일치와 기존 규칙 페이지 일부 구간의 모바일 넘침도 이번 범위에서 수정하지 않습니다.

최종 확인

운영 반영·규칙 배포·main 푸시 완료 · 최종 CI 통과

보안 보완 커밋 2fd29b8a의 CORE MCP 보안·화면 검사가 모두 통과했습니다. 운영 실행기의 MCP 의존성도 반영하고 252개 테스트·취약점 0건을 재확인했습니다. 10:58 KST 새 프로세스의 기존 소유자 인증·도구 8개·한정된 상태 조회가 정상이며 회원 쓰기는 0건입니다. 기존 앱 연결은 강제로 재시작하지 않았습니다.

배포 후 두 운영규칙 주소를 다시 조회해 HTTP 200·원본 해시 일치를 확인했습니다. 소스·배포용 main은 정리됐고, 운영 실행기의 기존 비추적 scripts/__pycache__/만 보존했습니다. 다른 대기자 관리 작업은 포함하지 않았습니다. 문서 증거를 추가하는 마지막 커밋은 실행 코드를 바꾸지 않습니다.

실제 회원 문자 시험·과거 건 수동 일괄 발송·수동 큐 실행·정본 회원 변경은 하지 않았습니다. 이번 검증은 향후 자연 정기 처리의 실제 접수·최종 전달을 대신하지 않습니다. 기존 대기 건은 원본·기존 발송 이력·시간 제한을 통과할 때만 처리됩니다.
