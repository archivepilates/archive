완료와 미완료

구현·검증

공식 SDK stdio 연결, 조회 도구 6개, 로컬 메모 계획·별도 승인·기존 큐 접수 코드. 독립 검토 보완을 포함한 격리 테스트 85건 및 실제 읽기 전용 MCP 연결 검증을 통과했습니다.

아직 운영 아님

Codex 설정 등록·상시 설치·커밋·푸시·main 승격·CORE Hosting 배포는 하지 않았습니다. 실제 메모 쓰기와 브라우저 E2E는 미실시·비활성입니다.

조회 원천은 기존 Firestore canonical 동기화·기능 원장입니다. StudioMate 실시간 원본 화면 조회나 전체 업무 제어를 완료한 것이 아닙니다.

중복·안전장치

  • 새 스케줄러·LaunchAgent·AI API 호출·공개 HTTP 포트를 추가하지 않았습니다.
  • 기존 자동화·기존 MCP 서버·공유 StudioMate 프로필은 그대로입니다.
  • 활성 운영자 권한을 매 호출 재확인하며, 임의 컬렉션·셸·브라우저 조작은 노출하지 않습니다.
  • 메모는 회원·내용으로 고정된 키를 사용하고 원장과 기존 큐를 하나의 트랜잭션으로 작성합니다. 실패·진행 중 작업은 자동 재접수하지 않습니다.
  • 승인은 모델의 approved 플래그가 아닌 별도 운영자 터미널 절차입니다. 같은 맥미니 OS 사용자 권한을 신뢰하는 로컬 방식이며 원격 다중 사용자 인증 수단이 아닙니다.
  • 같은 키 재실행·동시 요청·원본 변경·승인 만료·운영자 권한 해제·부분 원장·정보 마스킹을 격리 테스트했습니다.

실제 조회 검증

등록된 김기효 테스트 계정으로 실제 stdio MCP 클라이언트 → 서버 → Firestore → 구조화 응답 경로를 확인했습니다. 요약 로그에는 회원 개인정보를 남기지 않았습니다.

개발 중 보완

  • 계약의 회원 ID가 최상위에 없으므로 nested binding·selection·completion을 조회하도록 연결했습니다. 서명 증거의 회원·센터·계약 ID도 대조합니다.
  • 과거 테스트 원장에 다른 센터 문자열이 있어 엄격한 센터 쿼리로 제외했습니다. 해당 원장을 수정하거나 실제 대상에 포함하지 않았습니다.
  • 입력 키의 프로토타입 상속, 확인 화면 이후 계획 변조, 자유 형식 사유 코드의 개인정보 노출, stdin 종료 처리를 보완하고 테스트했습니다.
  • 메시지 날짜 범위를 원본 쿼리에 적용하고 미배포 인덱스에 한한 제한적 호환 경로를 명시했습니다.
  • 의존성 감사 후 새 서비스의 Firebase Admin만 갱신했습니다. 기존 운영 실행기 의존성은 변경하지 않았습니다.

남은 조건

  1. 독립 검토 결과와 최종 검증을 반영합니다.
  2. 운영 승격 요청 후 커밋·main 승격·푸시, 메시지 날짜 인덱스 2개와 Codex 조회 전용 연결을 진행합니다.
  3. 메모는 별도 승인된 제한 E2E·실제 원본 반영·로컬 계획 보존정책을 확정한 뒤 켭니다.
  4. 실시간 StudioMate 조회와 예약·취소 등 새 제어 도구는 공유 브라우저 잠금을 사용한 별도 어댑터로 추가합니다.

현재 키의 IAM은 기존 운영 서비스 계정 권한입니다. 조회 전용 제한은 서비스 코드에 있으며 IAM 자체를 최소권한으로 변경한 것은 아닙니다. 외부 공개 전 전용 계정·사용자 인증이 필요합니다.

메시지 날짜 인덱스가 운영에 없음을 읽기 전용으로 확인했습니다. 정의만 추가했으며, 인덱스 부재에 한해 최대 200개 고유 문서의 기존 회원 이력을 읽는 호환 경로와 미배포 상태를 명시합니다. 큰 이력은 인덱스 배포 필요로 중단하며 통신·권한 오류에는 대체하지 않습니다. 원본 최신성 증거가 없어 freshness는 unknown으로 표시합니다.

전용 브랜치 codex/mini/archivepilates-mcp-local의 services/archivepilates-mcp에 구현했습니다. CORE 운영규칙은 개발 상태를 명시한 로컬 초안만 추가했으며, 운영 서비스·규정이 바뀌지 않았으므로 라이브 배포하지 않았습니다.
