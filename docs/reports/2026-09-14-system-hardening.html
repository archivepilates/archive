1

프라이빗 Notion 반복 실패

회원 이름 변경 후 제목으로 기존 페이지를 찾지 못하던 문제를 회원 ID와 담당 강사의 기존 연결로 해결했습니다. 예약 ID가 변경된 차트는 다음 실행에서도 기존 요청을 재사용합니다.

실패 3건의 실제 페이지와 제목을 확인했습니다. 내용이 없는 중복 표시 2건은 기존 원본을 가리키는 별칭으로 정리했으며, 기록이나 답변을 삭제하지 않았습니다. 기존 별칭을 포함한 8건은 실패 집계에서 제외합니다.

2

Firestore 데이터 보호

DB 삭제 보호, 7일 시점 복구(PITR), 매일 백업·7일 보관을 설정했습니다. 별도 비공개 DB로 복제한 뒤 같은 시점의 원본과 대조했고, 인증 없는 접근이 403으로 차단됨을 확인했습니다. 시험용 DB는 삭제했습니다.

첫 정기 백업 생성은 아직 대기 중입니다. 설정 완료와 백업 파일 생성 완료를 구분하며, 최초 26시간 이후에도 백업이 없으면 기존 점검에서 보고합니다. 추가 보관 비용이 발생합니다.

3

배포 덮어쓰기·작업 삭제 방지

5개 Functions 코드베이스의 직접 배포에도 깨끗한 main, 최신 origin/main 일치, 프로젝트·경로 일치, 회귀 검사를 강제했습니다. 구형 Documents 배포본은 원래 설정을 백업한 뒤 배포 차단 처리했습니다.

워크트리는 원격 main에 병합되고 실행 중이지 않으며 사용자 파일이 없는 경우에만, 명시한 경로에 한해 삭제할 수 있습니다. 기본 실행은 점검만 합니다. 단순히 푸시됐다는 이유로 삭제하지 않습니다.

일부 타사 시스템 LaunchAgent/Daemon 설정이 끊어진 링크이거나 읽기 권한이 없어 실제 일괄 정리는 안전하게 차단했습니다. 기존 작업공간은 삭제하지 않았습니다.

4

StudioMate 브라우저 충돌 방지

45분이 지났다는 이유만으로 살아 있는 작업의 잠금을 지우던 경로를 제거했습니다. 같은 맥의 소유 프로세스가 종료됐고 잠금도 오래된 경우에만 회수합니다. 해제 시 고유 소유 토큰을 확인하고 동시 회수를 직렬화합니다.

실행 중인 Chrome, 사용자 창, 소유자를 확인할 수 없는 잠금은 종료·삭제하지 않습니다.

5

오래된 작업 폐기와 점검 정확도

6월의 옛 출석 쓰기 3건은 사유와 폐기 시각을 기록해 종료했습니다. StudioMate API 작업은 재실행하지 않았습니다. 정상 10분 주기 작업 3개와 의도적으로 중단한 작업 3개를 구분해 확인합니다.

대기 작업은 생성·실행 예정 시각으로 지연을 계산합니다. 최신 실패를 먼저 조회하고, 조회 오류·상한 도달을 정상 0건으로 숨기지 않습니다. 신규 인덱스 9개는 모두 READY입니다. 해결 여부는 고정 점검 키와 충분한 조회 증거가 있을 때만 갱신합니다.
