사용자 승인과 범위

기간 변경별 1회 자동 안내, 기존 승인된 홀딩 현황 안내 v2 재사용, 검증 후 맥미니 실행기·CORE 운영규칙 반영과 배포·커밋·푸시를 승인받았습니다. 템플릿에는 ‘등록되었습니다’라는 고정 문구가 그대로 남습니다. 변경 전후 비교용 새 템플릿을 승인받았다고 표현하지 않습니다.

활성화 이후 변경만 대상이며, 이번에 명시적으로 승인된 원본 변경 1건만 정확한 회원·최초 발급·원래 홀딩 생성·변경 지문으로 사전 예외를 둡니다. 과거 변경을 일괄 발송하거나 기존 등록 알림을 재발송하지 않습니다.

처리 흐름

  1. 기존 정기 Excel이 최근 수정·정지 상태를 발견하면 원본 조회 요청을 만듭니다.
  2. 공유 브라우저 잠금을 확보해 현재 수강권의 전체 이력·정지 목록·저장된 기간을 읽고 최초 계약기간으로 다시 계산합니다.
  3. 기존 등록 알림의 동일 원장·선점·제공자 이력을 먼저 대조합니다. 전달 완료가 확인되지 않으면 변경 안내로 넘어가지 않습니다.
  4. 수정 전후 날짜와 앞선 변경을 연결해 안정적인 변경키를 만듭니다. 동일 시각·끊긴 이력·여러 미처리 변경은 보류합니다.
  5. 전체 기존 홀딩 발송 이력, 승인 템플릿, 직원 제외, 현재 설정과 원본을 재검증하고 트랜잭션으로 변경키를 한 번 선점합니다.
  6. 매일 09:00 이상 23:00 미만에서만 요청합니다. 접수·실패·결과 불명확 요청은 재전송하지 않습니다.
  7. 검증된 접수 후 변경 전후를 명시한 새 메모를 생성하고 기존 5분 작업이 StudioMate에 append-only로 복사합니다.

유지한 보호장치

  • 기존 등록키·등록시각·원래 48시간 제한·기발송 변수·메시지 ID·메모는 불변입니다.
  • 변경 안내는 변경 시각 기준 48시간 제한을 별도로 적용합니다. 기존 접수의 GET 대조는 이 제한보다 먼저 가능하지만 새 전송은 제한을 우회하지 못합니다.
  • A→B→A도 각각 다른 이력으로 식별하며, 스캔·템플릿 버전·표시 순서로 새 키를 만들지 않습니다.
  • 앞선 변경이 이미 전달됐다면 다음 변경을 허용합니다. 앞선 미발송·접수 불명확 변경은 최신 기간 하나로 뭉개거나 중간 내용을 임의 발송하지 않습니다.
  • 자동 등록 정책과 변경 정책을 별도 설정으로 재검증합니다. 설정 변경·원본 변경·취소·범위 초과·전체 이력 미완전·잘못된 원장·중복은 발송 전에 차단합니다.
  • 시간별 수집·5분 메모·공유 잠금·기존 기준선·회원·수강권·홀딩·예약·발송시간은 변경하지 않습니다. 수동 큐나 수동 발송으로 검증하지 않습니다.
