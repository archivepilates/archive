StudioMate 실시간 업무 처리 기준

실시간 조회 운영 연결·CORE 운영규칙 Hosting 배포·등록 연결 검증 완료

빠른 답변과 정확한 실행은 다른 문제입니다. 저장 자료는 탐색과 분석을 돕고, 현재 상태의 확정 및 회원에게 영향을 주는 처리는 StudioMate 원본 재확인에 근거하도록 구분합니다.

확인한 현재 구조

개별 실시간 조회
회원 검색과 현재 수강권은 StudioMate 화면을 직접 확인합니다. 현재 수강권은 새로운 상세 화면에서 두 번 대조하며, 로그인·원본 조회 실패를 저장 자료로 대체하지 않습니다. 종료·삭제된 수강권 전체 이력 조회는 별도 범위입니다.
목록·예약 개선
만료 대상은 기본적으로 전체 원본 회원 페이지, 예약은 선택 회원의 이용내역 전체 탭을 요청 시 직접 읽습니다. source=snapshot을 명시해야 기존 저장 목록을 사용합니다. 계약·알림톡·작업 상태는 여전히 저장 원장입니다. 실제 예약·취소·환불 실행 도구는 없습니다.
최신성의 공백
기존 Excel 수집 LaunchAgent 설정은 3,600초 주기입니다. 만료 목록의 프로세스 메모리 캐시는 최대 300초지만, 캐시를 갱신해도 오래된 수강권 원천이 최신으로 바뀌는 것은 아닙니다. 원천 갱신 실패 시 실제 나이는 더 길어질 수 있습니다.
목록 완전성
기존 검증 기록은 저장 프로필과 전체 회원 Excel의 범위가 다르며 일부 수강권 배열이 누락돼 있음을 명시합니다. 이는 현재 전체 회원 수의 재집계가 아니며, 저장 목록을 전체 실시간 명단으로 부를 수 없다는 근거입니다.
브라우저 제약
실시간 도구는 공유 프로필 잠금을 최대 5초 기다리고 요청별 브라우저를 닫습니다. 전체 수집을 자주 실행하면 대화형 조회와 운영 실행기의 잠금 경합이 늘어날 수 있습니다.

기준 소스: 9f8f54a3. 변경: native-model·native-pages·freshness와 서비스·7개 조회 도구 계약. StudioMate 화면이 발생시킨 GET 응답만 최소 필드로 투영하고 직접 내부 API 호출·인증 헤더 추출·회원 데이터 쓰기는 하지 않았습니다.

실제 검증 결과

전체 원본 조회
1,036회원·21페이지·508개 현재 수강권 행을 조회했습니다. 첫 실행 약 28초, SDK 재시험 약 16초. 응답속도 보장값이 아니며 잠금 대기·통신에 따라 달라집니다.
10일 이하 만료
2026-10-16 한국 날짜 기준 33회원·34행입니다. 저장 목록은 626프로필, 원본 목록은 1,036회원이므로 결과 수가 우연히 같아도 범위가 같은 원천이 아닙니다. 원본 신원 필드가 불완전한 45프로필은 제외 수로 공개했으며 전체 적격 회원이 모두 포함됐다고 단정하지 않습니다.
개별 조회
반복 회원 검색 약 1.8~2.5초, 현재 수강권 약 3.0~3.1초. 정확 일치 검색·원본 회원 ID·이름·전체 전화번호를 대조하고 연락처는 결과에 마스킹합니다.
취소 이력
선택한 회원의 기존 취소 2건을 원본 전체 탭에서 확인했습니다. 예약 조회 약 1.4초이며 실제 취소를 다시 실행하지 않았습니다.
동시 변경 한계
complete는 페이지 순회 범위입니다. atomicSnapshot=false·pointInTimeComplete=false로 단일 시점 확정이 아님을 공개합니다. 회원 목록은 첫 페이지 재확인, 예약은 순회한 페이지 재대조를 수행하지만 모든 동시 수동 변경 검출을 보장하지 않습니다. 외부 작업 근거 사용은 금지합니다.

회원·수강권·예약·홀딩·발송·큐·기존 1시간 수집 주기는 변경하지 않았습니다. 조회 실패 시 저장 자료로 자동 대체하지 않으며 로그인·잠금·범위·변경·시간초과를 오류로 반환합니다.

제안하는 세 가지 조회 기준

1. 개별 회원의 현재 상태

“정유리 수강권”, “현재 남은 횟수”, “이수정 취소됐어?”는 요청 시 해당 회원·수강권·예약을 원본에서 다시 읽습니다. 저장 정보가 오래됐다는 이유로 조회 대상에서 빠지지 않게 원본 검색으로 진입하며, 선택은 원본 회원 ID·이름·전체 전화번호로 확정합니다.

검색용 짧은 캐시는 탐색 힌트로만 허용합니다. 잔여 횟수·유효기간·예약·취소 완료 같은 현재 상태는 원본 확인시각과 함께 응답합니다. 계약 서명·메시지 전달은 각각 해당 서비스의 확인 증거로 구분합니다.

2. 전체 범위의 조건별 목록

“10일 이하 만료 회원 전체”는 저장 목록에 포함된 사람만 재조회하는 방식으로는 누락을 해결할 수 없습니다. StudioMate의 전체 또는 검증 가능한 조건별 원본 목록을 먼저 확보하고 페이지·총건수·센터·중복·원본 ID를 대조한 뒤 조건을 계산해야 합니다.

즉시 갱신할 수 없다면 “동기화 자료 기준”과 원천 확인시각·누락 범위를 명확히 표시합니다. 전체 범위를 확보하지 못한 상태에서 “대상 없음” 또는 “전체 N명”으로 확정하지 않습니다. 빠른 미리보기와 원본 검증 완료 결과를 분리합니다.

3. 예약·취소·수강권·환불 관련 실제 처리

원본 조회 → 변경 계획과 영향 확인 → 사용자 승인 → 실행 직전 원본 재확인 → 한 건씩 처리 → 처리 후 원본 대조 → 완료 기록 순서로 구성합니다. 승인 후 대기열에 머물렀다면 실제 실행기가 원본을 다시 읽어야 합니다.

제안 기준은 변경 직전 확인이 30초를 넘었거나 관련 원본이 바뀐 경우 다시 확인하는 것입니다. 30초는 안전을 보장하는 유효기간이 아니라 재확인 상한의 초안입니다. 변경된 계획은 자동으로 승인된 것으로 간주하지 않으며, 실제 결제 환불은 별도 명시 승인 대상으로 유지합니다.

맥미니 잠금은 우리 자동화끼리의 충돌만 막습니다. 직원의 수동 조작이나 회원 앱까지 잠글 수 없으므로 실시간 조회만으로 경쟁 상태가 사라지는 것은 아닙니다. 실행 직전·직후 원본 검증과 불명확한 결과의 재시도 차단이 함께 필요합니다.

빠르게 만드는 순서

  1. 요청 범위를 한 번에 조회: 검색 후 확정한 원본 ID로 수강권·예약·계약을 묶어 읽고 불필요한 화면 왕복을 줄입니다. 같은 요청의 동일 조회는 합치되 권한과 확인 범위는 유지합니다.
  2. 전수 수집보다 필요한 범위 우선: 개별 업무는 해당 회원, 월간 업무는 해당 월·강사·수업 유형을 갱신합니다. 전체 Excel 수집을 모든 질문의 선행 조건으로 만들지 않습니다.
  3. 전체 목록 원천 보완: 기존 Excel의 전체 범위와 누락을 검증한 독립적인 읽기 모델을 마련합니다. 읽기 갱신이 연락처·계약·홀딩·발송 자동화를 뜻하지 않도록 분리하고, 원천 승격은 무발송 비교 후 진행합니다.
  4. 측정 후 수집 주기 결정: 조회·대기·수집·해석 시간을 따로 기록한 뒤 필요한 범위만 갱신합니다. 현재 시간별 전체 수집을 무조건 1분 주기로 줄이지 않습니다.

잠금이 없는 단일 회원 조회는 우선 5초 안팎을 개선 목표로 측정하되 보장된 응답시간으로 표시하지 않습니다. 전체 월간 목록과 복합 실행은 별도의 소요시간을 측정하고 대기와 진행 단계를 보여줍니다. 무거운 기존 작업을 강제로 끊거나 두 프로세스가 공유 프로필을 동시에 열지 않습니다.

구현 우선순위와 완료 기준

  1. 목록 원천과 최신성 표시: 현재 저장 목록의 전체 범위 오해를 없애고 누락·중복·지연·갱신 실패를 시험합니다. 새 가입·발급·해지·정지가 빠짐없이 반영되는지 원본과 대조합니다.
  2. 요청형 실시간 복합 조회: 회원·수강권·예약·계약의 확인 범위를 확장하고 잠금 대기, 로그인 만료, 화면 지연, 동일 조회 동시 요청을 검증합니다. 기존 자료로 조용히 대체하지 않습니다.
  3. 승인형 실행: 고정예약·수업 복제부터 계획과 승인 범위를 고정하고 실제 실행 전후 원본을 대조합니다. 고정예약은 대상 월 전체 예약 Excel로 누락·중복·잘못된 시간·계획 밖 예약이 없는지 확인해야 완료입니다.

이번 구현은 조회·최신성 메타데이터만 확장합니다. 고정예약·수업 복제·환불 등 실제 실행은 후속 개발이며 완료로 보고하지 않습니다. 모든 결과에 외부 작업 사용 금지를 유지합니다. 새 Firestore 컬렉션·미러·정기 수집·모델 API 비용은 추가하지 않습니다.

배포·검증 기록

기능 브랜치 codex/mini/mcp-freshness-policy에서 MCP 234건·공유 잠금 7건, CORE 반응형 로컬·라이브 각각 95건을 검증했습니다. 취소·시간초과 중 브라우저 종료가 잠금 해제보다 먼저 완료되는지 확인했습니다. npm audit 취약점 0건이며 CORE Hosting·롤백 가드도 통과했습니다. StudioMate 실시간 브라우저·잠금은 매 요청 finally에서 종료합니다. CORE 운영규칙만 Hosting 반영 대상이며 Functions·Firestore 규칙·운영 데이터 변경은 없습니다.

구현 커밋 cc9ac525를 origin/main과 기능 브랜치에 푸시하고 맥미니 운영 실행 경로에 반영했습니다. archive-pilates·archive-pilates-core Hosting 배포와 라이브 canary, 운영규칙 원본 파일 일치를 확인했습니다. 등록된 설정으로 새 stdio 연결을 열어 조회 7개·쓰기 차단을 재검증했습니다. 개별 검색 2.3초·수강권 3.0초·예약 1.6초·전체 만료 목록 14.0초였습니다. GitHub 검사 및 최종 기록은 대응 작업 파일을 따릅니다. 이전에 열린 Codex 연결은 MCP 재연결이 필요할 수 있습니다. 작업 소유 브라우저·프로필 잠금은 정리했습니다.
