판단

연결된 CORE MCP의 목록과 원장 1건 조회는 각각 약 0.84초와 0.76초에 응답했습니다. 이번 측정에서 연결 장애는 관찰되지 않았습니다. 방화벽·Tailscale·앱 전체 장애나 모델 지연의 원인은 확정하지 않았습니다.

전체 목록 반복 로딩과 같은 자료의 브라우저·DB 재조회는 줄일 수 있습니다. 긴 대화와 반복 heartbeat도 문맥량을 늘리지만 각각의 지연 기여도는 측정하지 않았습니다. CORE 저장자료 처리와 StudioMate 계약·수강권의 실제 외부 작업은 구분해야 합니다.

개선 및 실측

업무 요약을 기본값으로 하고 정확한 operation/area의 상세만 선택 조회합니다. 전체 메타데이터는 view=detail로 유지합니다. 수정 준비에는 업무별 주의사항을 추가했습니다.

검증·안전

테스트 250건 통과, diff 공백 검사 통과, 실제 별도 stdio 연결에서 업무 45개·영역 46개 유지와 제한 조회를 확인했습니다. 권한 매호출 확인·원본 최신성·중복·시간·결과불명 차단은 유지합니다. 회원 쓰기와 발송은 0건이며 브라우저를 열지 않았습니다.

운영 반영

사용자 승인 후 코드 7116defc를 GitHub main과 운영 실행 경로에 반영했습니다. 운영 경로에서 새 MCP 프로세스를 실행해 실제 읽기와 선택 상세를 확인했습니다. 회원 쓰기·발송은 0건입니다. CORE Hosting 버전 4c237fed08d311fe는 기존 63개 경로·설정을 보존하며 운영규칙 파일 하나만 교체했습니다. 공식 CORE와 Firebase 주소에서 HTTP 200 및 소스 해시 일치를 확인했습니다.

운영 경로 재검증: 전체 412ms/31,109B, 요약 415ms/10,750B, 선택 업무 422ms/3,539B, 원장 읽기 531ms. 현재 채팅의 연결은 여전히 이전 전체 목록 형식으로 확인됐습니다. 앱을 강제로 종료하거나 기존 MCP 프로세스를 죽이지 않았습니다. 이 채팅에 새 코드를 적용하려면 연결을 다시 맺어야 합니다.

CI 및 남은 단계

최초 CORE CI의 UI 검증은 새 운영규칙 라벨이 예상 목록에 빠져 실패했습니다. 해당 예상 목록을 갱신한 639c6a35를 main에 푸시했고, 로컬 320·390·768·1440px 검증 및 후속 CORE MCP Check 41014477418이 통과했습니다. 최초 Functions Affected Check 41014212263도 통과했습니다. 현재 채팅의 MCP 재연결은 별도 사용자 작업이며, 연결 확인 전 완료로 표시하지 않습니다. 채팅 이력·자동화·권한·발송 규칙은 변경하지 않았습니다.

현재부터 이미 확인한 지원 업무는 필요한 ID·필터로 직접 조회하고, 결과를 요약해서 사용합니다. 이 방식은 대화 삭제나 강제 문맥 초기화를 의미하지 않습니다.
