사용 흐름

휴대폰번호로 로그인 → 초기 비밀번호 변경 → 새 비밀번호로 다시 로그인 → 홈·프라이빗·시퀀스 노트.

초기 비밀번호는 사용자 결정에 따라 공통값을 사용하고 활성화코드나 자동 문자는 추가하지 않습니다. 변경 전에는 업무 API와 시퀀스 저장에 접근할 수 없습니다. 새 비밀번호는 8~64자이며 공통 초기 비밀번호를 다시 사용할 수 없습니다.

StudioMate 직원 전체 명단의 현재 근무 상태와 전화번호·고유 ID를 확인한 네 명만 포함합니다. 김기효와 기존 운영자 계정의 비밀번호·역할·권한은 변경하지 않습니다. 이후 입사자 계정은 운영자의 명시적 등록이 필요합니다.

권한과 원천

  • 현재 근무 상태: StudioMate 직원 탭 완전 스캔 → staffs 근무 메타데이터.
  • 프라이빗: 본인의 staffId·studioId와 연결된 canonical bookings 및 일치하는 privateLessonChartRequests만 서버에서 검증 후 표시.
  • 회원 연락처, 전체 회원 프로필, 정산·알림톡·직원 인증 원문은 강사 화면에서 조회하지 않음.
  • 시퀀스: 로그인 UID 본인의 sequenceNotes와 sequenceNoteImages만 접근. 다른 강사·운영자 저장본과 분리.
  • 메뉴를 숨기는 것과 별개로 API 및 Firestore 규칙에서 초기 변경 전·과거 세션·퇴사·비활성 계정을 차단.
  • 기존 근무 명단 동기화는 active·role·uid 및 연락처·급여·알림톡 규칙을 변경하지 않음.

  • 기존 CORE 반응형 화면 95조합 및 Hosting 라이브 canary 통과. 기능 소스 e237e8ea의 main CI 통과.
  • app·sync·alimtalk·social 및 두 Hosting 사이트, Firestore 규칙·READY 인덱스 반영: f0886adc.
  • HOME 관리자 재인증 후 최초 변경 함수만 전용 실행 계정으로 재배포: e237e8ea. 함수 ACTIVE 및 실행 계정 재조회 확인.
  • 격리 라이브 테스트: UI 비밀번호 변경 1회 → 새 로그인 → 이전 비밀번호·세션 차단 → 320/390/768/1440px 화면 → 민감 원문 조회 차단 → 본인 시퀀스·사진 저장/삭제 → 타 UID 접근 및 삭제본 복구 차단 → 비근무 차단 통과.
  • 시험 계정·저장본·사진·브라우저 모두 정리. 기존 관리자 문서·인증 보존.
  • 네 강사 초기 로그인·변경 필수 상태·변경 전 업무 접근 차단을 실제 API로 확인. 실제 강사의 비밀번호 변경은 하지 않았으며 본인이 진행해야 함.

최소 권한 보완

completeCoreFirstLogin만 archive-core-auth 키 없는 서비스 계정으로 실행합니다. 전용 Auth 역할은 firebaseauth.users.get 및 firebaseauth.users.update 두 권한만 포함하며 Firestore 사용과 로그 작성 권한을 별도로 부여했습니다. 사용자 생성·삭제·Auth 설정·발송 권한과 공유 실행 계정 권한은 확대하지 않았습니다.

초기 라이브 검증이 지연된 원인은 함수의 Auth 변경 권한 부족과 검증기의 IndexedDB·Firestore 배열 응답 해석 누락이었습니다. 권한을 좁게 보완하고 응답 형식 회귀 32건으로 재발을 방지했습니다. 실제 업무 차단은 정상 작동했으며 회원 발송·예약·결제에는 영향을 주지 않았습니다.

운영 주의

공통 초기 비밀번호만으로 휴대폰 소유자를 증명할 수 없습니다. 번호를 아는 제3자가 먼저 변경하는 위험은 남습니다. 강사에게 개별 안내하고 가능한 한 바로 최초 변경을 완료해야 합니다.

퇴사 차단은 다음 성공한 일일 StudioMate 전체 직원 스캔이 반영된 뒤 적용됩니다. 스캔 실패는 운영 점검 대상이며 즉시 차단이 필요하면 운영자 조치가 필요합니다.

기존 프라이빗 기록·리포트는 전달된 비밀 링크 기반의 별도 흐름입니다. CORE는 담당 수업과 일치하는 링크만 제공하지만 CORE 로그아웃이나 근무 상태 변경이 이미 전달된 비밀 링크 자체를 폐기하지는 않습니다.

반영 범위

기존 기능 릴리스의 CORE Hosting, app·sync·alimtalk·social 인증 가드, Firestore 규칙·조회 인덱스는 유지합니다. 이번 보완은 최초 변경 함수 실행 계정, 승인된 네 명의 계정 준비, 검증기와 운영규칙입니다. 회원·수강권·예약·홀딩·결제·메시지 발송은 변경하지 않았습니다.

계정별 내 시퀀스 분리는 라이브 검증 완료했습니다. 관리자의 전체 시퀀스 통합 조회는 별도 작업 공간에서 로컬 검증된 상태이며 아직 배포하지 않았습니다. 기존 시퀀스 소유권은 변경하지 않았습니다.

이 결과 문서와 운영규칙의 최종 Hosting 배포 상태는 커밋 후 배포 로그·라이브 운영규칙·릴리스 manifest로 확인합니다.
