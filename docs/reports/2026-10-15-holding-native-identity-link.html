홀딩 원본 회원 연결 보강

기존 회원 문서를 보존하면서 검증된 StudioMate 원본 ID 연결을 홀딩 처리에 사용합니다.

변경 범위

  • 원본 ID 연결과 완료된 ID 조회 기록의 회원·센터·이름·연락처·확인시각을 함께 검증합니다.
  • 새 숫자 ID 회원 문서는 만들지 않고 기존 Excel 문서를 읽습니다. 기존 수강권·계약·연락처·발송 이력은 이동하지 않습니다.
  • 발송 선점 트랜잭션에서 연결과 중복을 재확인합니다. 스텝 제외 등 기존 회원 필드는 그대로 사용합니다.
  • 기존 숫자 ID 회원 원장이 있으면 그 원장을 우선하며 잘못된 원장을 다른 연결로 우회하지 않습니다.

유지한 안전장치

기존 1시간 정기 실행, 10월 8일 신규 등록 기준, 48시간 초과 시 보류, 최초 기간 20% 소수점 버림, 취소·중도 해제 검증, 발송 직전 원본 재조회, 고정 중복 키, SOLAPI·후보·발송·선점 원장 대조는 변경하지 않습니다.

실제 회원 알림톡·수강권·정지·예약을 테스트로 만들거나 변경하지 않습니다. 무발송 검증과 실제 전달 완료를 구분합니다.

검증과 반영

운영 반영·라이브 검증 완료. 홀딩 Node 테스트 553건, TypeScript 테스트 236건, 스텝 제외·발송 정책 36건과 가격 회귀 5건이 통과했습니다. 320/390/768/1440/1920px 화면 검사도 로컬·라이브 각각 95건 통과했습니다.

  • 검증 대상: 원본 연결·조회 작업 불일치, 연결 철회·변경, 중복 전화번호, 무결성·동시 실행·접수 불명확·스텝 제외.
  • 원본 회원 1명의 실제 연결을 일반 조회와 읽기 전용 트랜잭션으로 확인했습니다. 기존 필드 보존과 중복 회원 미생성을 확인했으며 해당 홀딩 후보·발송·선점 원장은 모두 0건이었습니다.

남은 확인

예정 홀딩이 Excel에 노출되지 않으면 정기 감지가 아직 되지 않을 수 있습니다. 원본의 현재 정지 날짜칸과 생성 이력이 모두 확인되어야 발송할 수 있습니다. 연결 보완만으로 자동발송 완료를 주장하지 않습니다.

첫 자연 발생 운영 발송은 SOLAPI 최종 전달 상태와 동일한 후보·발송·선점 원장을 대조해 별도로 판정합니다.

  • 구현 커밋 8f6e91dea039ec74196bad4057cd762dcba9dae1을 main과 작업 브랜치에 푸시했습니다. 맥미니 실행기는 정기 작업이 유휴 상태일 때 같은 소스로 fast-forward했습니다.

  • 라이브 반응형 검사 95건과 배포 canary 10개 확인 항목이 통과했습니다. 공식 도메인과 web.app의 운영규칙 HTML은 로컬 소스와 SHA-256이 일치합니다.
  • 운영 실행기에서 원본 ID 연결과 읽기 전용 트랜잭션을 다시 검증했습니다. 기존 회원 필드를 보존했고, 중복 회원 문서와 해당 회원의 홀딩 후보·발송·선점 기록은 생성되지 않았습니다.

  • 작업 소유 브라우저·로컬 서버·임시 프로필은 정리했습니다. 첫 자연 발생 자동발송의 실제 전달 완료는 별도 확인 대상입니다.
