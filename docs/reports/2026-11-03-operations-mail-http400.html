확인한 원인

운영 업무 라벨이 20개에서 21개로 늘어난 뒤 동일 Pub/Sub 주제의 Gmail watch 갱신이 HTTP 400 invalidArgument, Too many labelIds specified로 거부됐습니다. 메타데이터 권한으로 프로필·라벨·변경 이력·미처리 운영메일 메타데이터는 정상 조회됐으며, 인증이나 메일 본문 권한 부족이 아니었습니다. 원래 커서와 원장을 초기화하지 않았습니다.

수정

구독은 기존 공통 상태 라벨 4개만 사용하고 세부 업무 라벨은 전부 변경 이력 조회와 분류에 유지합니다. 일반 메일함 전체·SENT 구독, 라벨 임의 삭제·잘라내기, 새 권한·라벨·예약기는 추가하지 않습니다. 공통 상태 라벨이 없는 운영메일은 기존 5분 유지 작업에서 보완 수집합니다.

오류 단계와 사유는 허용된 고정 코드만 기록합니다. Google 오류 원문·메일 제목/본문·주소·토큰은 진단 상태나 로그에 복사하지 않습니다. 기존 메시지 ID 중복방지·검토 상태·커서·활성화 기준을 유지합니다.

배포와 실제 수신

구현·오프라인 검증 진행 중입니다. 필요한 대상은 기존 수신/유지 Functions 두 개와 CORE 운영규칙이며, 실제 배포와 원본 메일 수신 결과는 각각 독립 확인 후 이 보고서에 기록합니다.

한계
