릴스 공개 승인과 백그라운드 운영

반복 채팅 예약을 별도 제작 작업으로 전환하고, 메일 답장 대신 승인 버튼을 사용합니다.

운영 방식

  1. 오전 9시 별도 예약 작업에서 릴스 한 편을 준비하고 일부공개 검토 영상과 승인 버튼을 메일로 보냅니다.
  2. 메일의 공개 승인 버튼으로 확인 페이지를 열고, 해당 영상의 공개 승인을 누릅니다. 답장은 필요 없습니다.
  3. 맥미니의 처리기가 5분마다 접수된 승인을 확인해 하루 최대 한 편만 공개합니다. 맥미니가 켜져 있고 깨어 있어야 합니다.
  4. 완료·처리 실패는 메일로 알립니다. 변화 없는 상태는 이 채팅을 깨우지 않습니다.

안전 기준

  • 메일 보안 검사, 링크 열기, 화면 초기 조회만으로는 승인되지 않습니다.
  • 승인은 특정 영상·검토한 제목 및 설명·파일에 연결되며 링크는 7일 동안 유효합니다.
  • 내용 변경 시 새 승인이 필요합니다. 같은 승인·공개·메일을 반복 실행하지 않습니다.
  • 원본당 릴스 최대 2편, 날짜당 새 업로드·공개 각각 최대 1편 제한을 유지합니다.
  • 기존 영상, 상품, 회원, 구매자 이력과 접근권한은 변경하지 않습니다.

검증 결과

  • 승인 전용 서버 배포 및 HTTP 200 응답, 잘못된 승인 요청 HTTP 403 차단 확인.
  • 테스트 메일의 승인 버튼과 안내 문구를 보낸메일에서 독립 재조회했습니다.
  • 통제된 테스트 요청은 링크 열기 후에도 승인 대기였고, 명시적 모바일 버튼 클릭 후에만 승인이 저장됐습니다.
  • 테스트 승인은 실제 공개 처리 대상에서 제외됐으며 실제 영상의 새 업로드·재공개는 없었습니다.
  • 320·390·768·1440 너비에서 가로 넘침 없이 표시됐고 터치 영역은 약 52px였습니다.
  • 승인·원본 대조·일일 한도·재처리·알림 영수증 테스트 22개와 배포·메일 회귀 테스트 38개 통과.
  • 5분 처리기 설치 및 첫 실행 종료 0, 오류 로그 없음. 작업용 브라우저 탭 종료·화면 크기 복구 완료.

functions-social / approveYoutubeReel, CORE 운영규칙, 로컬 처리기 및 별도 예약 설정만 변경합니다. 다른 Functions·아임웹·판매원본·회원 데이터는 변경하지 않습니다.
