  • 기존 알림톡 전달 결과를 GET으로 대조한 뒤 같은 발송 ID의 메모만 생성했습니다. 알림톡 재발송은 없습니다.
  • 18:31:42 KST 메모와 작업을 원자적으로 생성, 18:31:58 KST 기존 처리기로 반영했습니다.

  • 총 가능 24일·사용 22일·잔여 2일을 기록했습니다. 이번 완료는 승인된 단건 복구이며 새 정책의 자연 자동 실행 증거는 아닙니다.

정상 발송 접수의 불변 증거로 메모를 준비합니다. 기존 메모 큐가 StudioMate 사본을 추가합니다.

공통 조회

CORE·MCP가 같은 백엔드에서 감지·접수·전달·메모의 서로 다른 증거를 읽습니다.

접수 후 메모 연결
새 발송만 holding_acceptance_memo_v2에 등록합니다. 기존 발송 직후 수신자·본문·변수·템플릿·메시지 ID 확인을 재사용하며 최종 전달 대기를 제거합니다. 추가 공급자 조회는 없습니다.
기존 건 보존
holding_delivery_memo_v1은 전달 완료 기준을 유지합니다. 과거 발송 일괄 등록, 동일 건의 정책 변경, 완료·재시도 작업 초기화는 하지 않습니다.
메모 처리
정상 접수 후 준비된 원장만 기존 5분 처리기가 읽습니다. 메모에는 발송 접수라고 쓰며 전달 완료라고 쓰지 않습니다. 기존 브라우저 잠금·추가 전용 쓰기·전체 내용 재확인을 유지합니다.
실패 분리
접수 불명확·수신자/내용 불일치·거절은 보류합니다. 나중에 전달 실패가 확인돼도 정상 접수 당시 감사 메모를 전달 완료로 바꾸거나 발송을 재시도하지 않습니다. 메모 오류는 메모 작업에만 한정합니다.
동시 실행
불변 발송 키에 연결된 같은 메모 ID를 사용합니다. 원자적 메모/작업 생성, 완료·검토 상태 보존, 응답 유실 후 기존 접수 증거 보존으로 중복 실행을 막습니다.

CORE·MCP 조회

CORE 자동화 화면의 홀딩 처리 현황과 알림톡 목록의 진행 상태 링크, MCP의 operations_get_progress가 같은 읽기 전용 검사기를 사용합니다.

정확한 업무 ID 한 건으로 기존 6개 문서만 읽습니다. 전체 회원·예약 재계산, 공급자 호출, 큐 실행, DB 수정은 하지 않습니다. 활성 운영자 권한과 센터 범위를 검사하고 이름·연락처·메모 본문·임의 오류 문자열은 반환하지 않습니다.

단계는 원본 등록 증거 / 원본 확인 / 발송 접수 / 전달 결과 / 메모 접수 / StudioMate 반영입니다. 표시 시각은 저장된 증거의 시각이며 공급자 실제 전달 시각·실시간 원본 확인과 혼동하지 않습니다.

다음 확장 순서

  1. 회원등록 계약서 → 서명 → 웰컴 상태 조회를 같은 공통 상태 형식으로 연결. 기존 발송·계약 규칙은 재사용.
  2. 설문 → 강사 기록 → 리포트 → 메모의 중단 지점과 후속 작업을 표준화. 민감 응답은 권한 있는 원본 화면에만 표시.
  3. 예약·취소·환불은 조회부터 연결. 실행은 별도 승인, 직전 실시간 재조회, 예상 변경 검토, 고유 작업 키와 원본 재검증을 갖춘 뒤 단계적으로 추가.

이번 구현에는 예약·환불 실행, 계약 재발송, 기존 전체 후보 생성 구조 변경이 포함되지 않습니다.
