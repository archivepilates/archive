알림 수신과 기존 갱신 큐 연결

브라우저 알림목록 수집·중복 차단·기존 원본 갱신 요청 연결을 구현했습니다. Chrome Web Push 직접 수신이나 완전한 실시간 웹훅은 아닙니다. 홀딩과 기존 발송은 원래 경로를 유지합니다.

구현

  • 기존 30초 admin-sync 실행기 안에서 2분마다 최신 알림목록을 읽습니다. 새 LaunchAgent·발송기·모델 호출·공개 포트는 없습니다.
  • 첫 15건은 무처리 기준선입니다. 새 예약·취소·수강권·계약 알림은 기존 adminSyncRequests의 emergency_excel 요청만 만듭니다. 대기 요청과 합치며 추가 갱신은 최소 15분 간격입니다.
  • 내용 해시·순서 창·관찰된 재등장으로 신호를 구분하고, 같은 요청 키를 Firestore 트랜잭션으로 생성합니다. 반복 수신·시간 표시 변경·재시작·경쟁 생성이 별도 실행을 만들지 않습니다.
  • 알림은 원본 재조회의 힌트일 뿐 회원·예약·발송의 정본 ID가 아닙니다. 화면에 없는 변경과 구분할 수 없는 동일 알림의 반복은 기존 시간별 Excel로 보완합니다.
  • 전체 Excel 실행 잠금은 다운로드부터 반영·보고까지 유지합니다. 브라우저 잠금은 별개입니다. 시간별 실행은 대기하고 요청 실행은 중복 시작 대신 보류합니다.
  • 알림 요청은 홀딩 roster·발송, 계약 생성·완료 확인·서명요청 문자, 연락처 후속 처리와 강사 sidecar를 실행하지 않습니다. 연락처 원장의 hash/status도 보존해 다음 정기 동기화가 누락되지 않게 합니다.
  • 알림 갱신 보고서와 automationStatus는 정상 시간별 보고서와 분리합니다. 종료된 하위 프로세스·불완전 다운로드·부분 결과를 정상 성공으로 표시하지 않습니다.
  • 알림목록 읽기 3회 연속 실패 시 운영 메일과 복구 알림을 사용합니다. 범위 연속성 미확인은 경고로 표시합니다. 브라우저 종료 불명확 시 공유 프로필 잠금은 보존하고 기존 요청 처리는 계속합니다.
