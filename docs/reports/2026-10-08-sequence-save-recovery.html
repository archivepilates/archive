확인된 원인

메뉴 진입 시 가장 최근 노트를 자동으로 열었고, 이후 입력과 저장 버튼이 같은 문서 ID에 자동 저장했습니다. 실제로 한 문서가 코어 & 칼로리 버닝 → 척추 컨디셔닝 → 복부 옆구리로 변경됐습니다. 동시 수정 방지 기능은 있었으나 새로운 수업과 기존 수업 수정의 구분이 부족했습니다.

저장 방식 변경

  • 메뉴 진입과 새로고침은 새 빈 시퀀스에서 시작합니다.
  • 기존 기록은 목록의 수정으로 열고, 다른 수업에 활용할 때는 사본 만들기를 사용합니다.
  • 상단 새 시퀀스를 모바일과 데스크톱 모두에서 사용할 수 있습니다.
  • 화면 전환 전 변경분 저장을 확인하고, 저장 실패 시 전환을 중단합니다.
  • 백업은 서버의 최신 목록을 다시 조회하며 문서 ID와 내용 ID가 다르면 읽기를 차단합니다.

검증 및 배포

로컬 작성·저장 회귀 15건, 로컬·운영 CORE 반응형 각각 95개 화면 조합, Hosting·릴리스 보호 검사 및 수강권 가격 회귀 5건 통과. 운영 배포 커밋은 64bbdd73cdca6c3b14fb453f830a53d3e053dc56입니다. CORE 도메인과 web.app 호환 경로의 릴리스 확인 및 편집기·저장 어댑터 소스 해시 대조를 통과했습니다.

격리 시험 계정으로 실제 Firestore A 저장 → 새로고침 후 빈 노트 → B 저장 → 두 원본 공존과 A 내용 보존 → 새 시퀀스 → A 명시적 수정 → 다른 기기 충돌 차단 → 사본 저장과 B 보존 → 사진 삭제를 모두 확인했습니다. 테스트 전용 문서·사진·인증 계정은 삭제 후 0건을 확인했고 브라우저도 종료했습니다. 기존 운영자 문서 3건의 내용·버전·삭제 상태는 복구 전과 같습니다. 라이브 화면에서도 복구된 두 수업과 수정·사본 만들기 버튼, 전체 4개 목록을 확인했습니다.

변경 파일: 시퀀스 편집기, Firestore 저장 어댑터, 격리·운영 검증 스크립트, 제한된 시점 복구 도구, CORE 운영규칙과 작업 기록. 회원·예약·알림톡·StudioMate·Notion·인증 정책은 변경하지 않았습니다. Functions·Firestore 규칙·인덱스는 배포하지 않습니다.

보관과 한계

복구 전 원본·조회한 이력 증거·적용 결과는 운영 호스트의 비공개 백업에 보관하며 Git 또는 웹에 공개하지 않습니다. 한 시간보다 오래된 시점 복구 자료는 분 단위이므로 제목 변경 직전 마지막 1분 이내의 입력까지 복구했다고 보장하지 않습니다. 시간대별 제목 비교는 짧게 존재한 중간 제목이나 같은 제목의 모든 수정 이력을 망라하지 않습니다. 확인된 이전 두 수업을 복구한 결과이며 전체 버전 기록 복원은 아닙니다. 이미 열어둔 다른 기기의 편집기는 저장 완료 확인 후 새로고침해야 새 버전이 적용됩니다.
